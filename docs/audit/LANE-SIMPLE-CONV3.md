## 3. KD-1／KD-2／RG-634 と承認済み差分の成立維持

回帰テストと同じローダー（高度エンジンフック適用）で対象ビルドを直接確認：

- **KD-1（RG-606）**：名前付き結果表の読み取り `getResult("X", 0, "ProbeTable")` → `42`。既定表（省略形・"Results" 明示）→ `7`／`7`。`IJ.renameResults` 後の新タイトル解決 → `7`。存在しないタイトルは名前を挙げて停止。
- **KD-2（RG-607）**：`Color.setLut`／素の `setLut` のどちらで保持しても `Color.getLut` が保持LUT（255／0／99）を返す。対照（setLut なし）は単位LUT（0／255／10）のまま。
- **RG-634**：`setNames(c(1, 2, 3), "a")` の print が `c(a = 1, 2, 3)`（[object Object] なし）。全名付き対照も `c(a = 1, b = 2, c = 3)` で正常（正本では setNames 自体が未対応停止＝統合ビルド側の実装）。
- **LP-24（ImageJ eval）**：`eval("print(1)"); print("AFTER");` は「未対応：eval はモデルで未対応です」で停止し AFTER は出力されない。正本と同一。
- **承認済み差分（RG-671、cmd 変数展開モディファイア）**：対象は `%NAME:~0,3%` → `abc`、`%NAME:c=X%` → `abXdef` を出力（実 cmd の SET 意味論どおり、項目宣言と一致）。正本は未対応停止＝裁定どおりの差分として維持。
