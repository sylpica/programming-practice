## 1. 新規実質欠陥2件と修正（検証済み）

### 欠陥1：`std::pair` クラス項目の正規の例が実行不能（新規・中〜低）
- 内容：status=supported・caution なしの `std::pair` 項目の例 `std::pair<int, std::string> p{1, "one"}; auto n = p.first;` が「未対応:auto の型推論はコンテナ・イテレータ・pair の初期化子だけ対応します（スカラーは未対応です）」で止まり、開示なしに実行できない。対応288件の例の全件再実走（tier1 249／tier2 29／失敗10）で新規失敗として検出された1件（残り9件は B8 生記録と一致する既知分：文脈前提不足8件は拡張文脈で全件成功を確認、`std::forward` は caution 開示どおり）。
- 修正：例文を `int n = p.first;` 形へ変更（`js/types/cpp/reference-advanced-part3.js`）。pair の機能自体（make_pair・メンバアクセス・swap）は CPP-16／22 で正常であり、不整合の所在は例文側にあった。
- 検証（仕上げ担当の実測）：新規回帰テスト A8収束-1 が、カタログ実物の例をそのまま simulate してエラーなしを確認。手作業の再現でも明示型の形は出力 `1 one` で正常実行。

### 欠陥2：`std::NULL` が未対応表示に反して黙って成功（低・前回からの未解消残存）
- 内容：status=unsupported・caution「コンパイル時に評価・解決される仕組みのため、実行シミュレーションの対象外です」の項目が、入力 `std::cout << std::NULL;` に対してエラーなく `null` と表示して成功する。実 C++ に `std::NULL` は存在しない。未対応スイープ305件の再実行で「黙った成功」の残存1件として再検出された。
- **経緯（重要）**：この欠陥は前回ラウンドで既に検出されていた。前回所見 `lane-a8-exec/docs/audit/lane-a8-work/findings-cpp-stop.md` §2-2(f) および同欠陥表 #9 に「低」と記録されたが、「基礎側の NULL リテラル表示と同根の可能性があり、本班では A8 の項目データ側の所見に留める」とされ、前回の修正13件（A8-1〜13）には含まれず未解消のまま統合ビルドへ残存した。本ラウンドで再検出され、今回初めて修正された。
- 根本原因：変換層（transformSource）が `std::` を落として名前を基盤エンジンへ渡すため、`NULL` が基盤の NULL リテラルとして評価されていた。
- 修正：`js/core/c-family.js` の変換層に、言語が cpp の場合のみ `std::NULL`（単語境界つき）を名指し停止する分岐を追加（「std::NULL は未対応です」）。
- 検証（仕上げ担当の実測）：再現スクリプトで `std::cout << std::NULL;` が未対応の名指し停止となり出力なしを確認。対照として無修飾 `NULL` は従来どおり `null` と表示され（C 言語側の NULL リテラルにも影響なし。分岐は language === "cpp" に限定）、`std::nullptr` の挙動も不変であることを回帰テスト A8収束-2／-3 で確認した。
