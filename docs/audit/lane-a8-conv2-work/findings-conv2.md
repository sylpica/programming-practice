## 2. 第1回欠陥2件の修正の成立確認

### 欠陥1：std::pair の正規の例が実行不能 → 解消
- カタログ実物の例は `std::pair<int, std::string> p{1, "one"};\nint n = p.first;` に差し替わっており、そのまま simulate してエラーなし・出力 `1 one`（repro-defects.mjs）。
- examples 全件実走で std::pair が失敗一覧から外れた（tier1 +1）。
- なお旧形 `auto n = p.first;` は今も「auto の型推論は…スカラーは未対応です」で止まるが、これは例文側の不整合が欠陥だったのであり、auto スカラー推論の未対応自体は正直な名指し停止で欠陥ではない。

### 欠陥2：std::NULL が黙って成功 → 解消
- sweep の全305件で第1回と変わったのは std::NULL の1件のみ：`silent-success（出力 "null"）` → `named-stop「未対応:…：std::NULL は未対応です」`、出力なし。
- 波及範囲のスポットチェック（spot-null-scope.mjs）：cpp の `nullptr` 代入・比較は正常（出力 1）、無修飾 `NULL` は従来どおり `null` 表示・比較も正常、C 言語側の `NULL` 使用も不変。
- 構造的な裏付け：バッチ18のエンジン差分は c-family.js の cpp 限定分岐9行のみ（`git diff 4771801 4f41e11 -- js/core/` で確認）。C／C# の経路には物理的に触れていない。
