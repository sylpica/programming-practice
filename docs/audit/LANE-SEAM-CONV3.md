## 1. バッチ19の3修正の継ぎ目確認（独立ハーネスで再検証）

統合班の回帰テストとは別に、本班が独自ハーネス（エンジン直叩き）で3修正の継ぎ目面を確認した。

- **RG-675（ImageJ trace 照合）**: 基礎照合状態では `Color.toString` を含むコードは「Color.toString はモデルで未対応です」と正直に停止し refs は空（基礎データに項目が無い以上、照合で項目化されないのは正）。高度では出力 `"red"` を返し、trace の参照解決に `Color.toString` と `print` が正規名で現れる。修正は trace 面に閉じ、scan／実行結果は不変。
- **RG-676（NULL 等価）**: C 簡易で `NULL == 0`→`1`、`NULL != 0`→`0`、ポインタ変数 `p == 0`／`0 == p` との混在式も `11` と正しく評価。C 高度でも同一（モードで実行結果は変えない不変条件を満たす）。C++ でも `nullptr == 0`→`1`／`nullptr != 0`→`0` が両モードで成立。なお C++ の `std::NULL` は「std::NULL は未対応です」の名指し停止のまま不変（RG-659 の事前検査層が先に働く既存の正直な停止で、本修正の対象外）。
- **RG-677（UI.Vision refs 正規化）**: 大文字形 `EXECUTESCRIPT` が実行され（出力 `2`）、trace の参照解決は原文綴りではなく正規名 `executeScript` で現れる。`CSVSave` も正規名 `csvsave` で解決する。実行意味論は不変で、変わるのは trace の照合名のみ。
