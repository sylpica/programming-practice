## §5 残件・観察（処置対象外として記録）

1. **PS @() 内の代入文の出力意味論（未確認候補）**：RG-354 のスイープで @() 内の代入式は現行モデル（右辺位置で従来受理されていた形）に揃えて受理としたが、実 PowerShell では @() は文リストであり括弧なし代入文は出力しない可能性が一次情報から示唆される。pwsh 実走なしに確定できないため既存裁定は変えていない（要 pwsh／CI 実走での確定）。
2. **PS 文位置のリテラル単体代入**：`5 = 3` 等の文位置形は従来文言のまま（虚偽原因ではなく、バッチ10ピン留めと同経路のため一括変更を回避）。式位置は RG-354 で名指し済み。
3. **C++ `std::string` 配列要素の読み取り**：要素の読み取りが `"\u0000"` になる既存不具合（HEAD a5967d6 から存在し、本バッチの9件とは無関係。要素への代入は RG-357 で受理済み）。次回監査での切り分け対象として記録する。
4. **C# 複数型引数ジェネリック型宣言**：`Func<int, int>` 等が `= null` でも「; が必要です」で停止する（HEAD からの文法制約で、RG-351 のラムダ名指しとは独立）。
5. **括弧なし `return 1, 2;` のカンマ**：RG-356 の実装範囲（括弧内・for・while・文位置の式文）には含めていない。
6. **RG-359 の範囲外**：変換が存在しない組合せ（例：`foreach (string v in int[])`）を黙って反復する受理の緩さは、バッチ10 §5 の既知として変更していない。
7. **統合環境の事象**：本バッチの作業中、exec からの repo 由来ファイル内容の書き込みが断続的に "Operation not permitted" で遮断される事象が発生した（内容依存のブロックと切り分け）。各班はシンボリックリンク／ハードリンクのファーム＋編集対象の実ファイル化、書き込み復旧後の実コピー等の代替構成で作業し、統合は rename（mv）経路で実施して全ファイルの sha256 一致を検証した。repo-reffix 本体の原本性（HEAD a5967d6・クリーン）は各班の着手時・終了時と統合側で確認している。統合報告書 `findings-round32.md` の §2 詳細が保存時に欠落していた点（班別報告には完存）もあわせて記録する。
