- 対象：同梱の `consolidated-residual-register.md`（以下「台帳」）の RG-01〜RG-41 の全41グループ（元項目135件：P2 ×24、P3 ×111。第14ラウンド系の R14-N2 と R14B-N1 は同一欠陥のため台帳で RG-39 に統合済み）。各項目の再現手順は台帳の「統合元」（元ファイル名＋項目ID）を参照すること。再現コードと期待挙動は、同梱の findings ファイル群に全部ある。

## 1. 修正の大原則（監査の裁定から）

1. **誤った値の捏造と、虚偽の原因表示は不可。** 実装できない構文・機能は、構文名・機能名を挙げた「未対応」の正直な宣言で停止し、宣言（DEVELOPMENT.md の対応・未対応リストと台帳の扱い）を実装と一致させること。正直な未対応化は劣化ではなく、受理可能な修正として扱う。
2. **受理して捨てる経路を作らない。** 引数・構文・節を受け取って無言で無視する実装は、新たに作らないこと。既存の該当経路はこの原則で改める。
3. **表示は言語の正規表記に合わせる。** trace・出力・最終状態の3表面で矛盾させない。実在しない表示形式を作らない。
4. **横断的な基盤の共通化を優先する。** RG-06／07／08／09／10 は「未対応を正直に宣言する」仕組みの共通化でまとめて改善できる。RG-04 は値整形の種類別化として横断的に実装する。個別パッチの積み重ねで表面ごとに食い違う実装にしないこと。

## 3. 再検証の要求（多角検証）

修正後は、修正した側自身が次の角度で再検証し、結果を数値で報告すること（Muse 側の独立再監査も別途行う）。

1. **ブラインド再導出**：答え（期待挙動）を見ずに、各言語の一次資料（公式ドキュメント・マニュアル・実物ソース）から期待値を再導出し、実装と照合する。特に RG-02／03／05／11／12／21 は実物（実 R、実 C#、実 VBA 規則、Power Fx 公式仕様）との照合を必須とする。
2. **実コンパイラ・実ランタイム照合**：C／C++／C#／Python は実コンパイラ（CI）で、R は実 R で、修正対象の再現コードを実物でも実行して一致を確認する。
3. **テストの全量実行**：既存テスト全件を実行し、失敗0を確認する。失敗を隠すためのテスト削除・緩和はしない（テストを変える場合は理由を CODEX-R4.md に明記）。
4. **実ブラウザ実地**：公開前のローカルビルドで、13種類の教材テンプレート全件の実行・パス切替・チップ・解説リンクを実際に操作し、RG-28／29／37 の受け入れ条件を確認する。375px 幅と広幅の両方で、文字の切れ・はみ出しがないことを確認する。
5. **ファズ／境界**：今回修正したパーサ・式評価の周辺（リテラル、演算子、引数パターン）をランダム・境界入力で叩き、新たな誤値・虚偽原因・無言消失が出ないことを確認する。
6. **再現コードの回帰確認**：台帳の統合元135件の再現コード全件について、修正後に再実行し、結果（動作／正直な停止／正しい値）を CODEX-R4.md の表に RG 単位で集計して示すこと。

## 6. 配信ルール（承認カードを増やさないための確定ルール）

- **節目一括**：配信は節目単位にまとめ、書き込みコールは最小構成とする。push-files 1回（全ファイル集約）＋必要な場合のみ PR 作成1回・マージ1回。小さい修正の逐次配信はしない。
