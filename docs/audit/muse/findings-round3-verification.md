## 6. 新規欠陥

### R3-N1（P3）AutoHotkey の文形式呼び出しで、引数が単項 +/− で始まると誤導的な NameError になる
- 再現（現行 0ee8c7a、Node エンジン、AHK モデル event=null）：`MsgBox -3`／`MsgBox -"3"`／`MsgBox +3`／`ToolTip -3` がいずれも「NameError：未定義の名前：MsgBox（ToolTip）」で停止する。
- 実測の切り分け：`MsgBox(-3)` → `-3`、`MsgBox (-3)` → `-3`、`x:= -3` ＋ `MsgBox x` → `-3` は正常。壊れているのは「文形式（括弧なし）呼び出しで最初の引数が単項 +/− で始まる」経路だけ。
- 欠陥の本質：MsgBox は未定義ではないのに「未定義の名前」と誤った原因を表示する。R2-N3 で問題にした「誤導的なエラー」と同種。値は誤って提示されず、明示的に止まる点は F4 等と同じ安全側。
- 回帰ではない：修正前 636f8d0 でも同一挙動を再現（第1・第2ラウンドでも未検出だった既存欠陥）。Codex の R3-F2 の検証範囲（代入・括弧形式の単項式）とは別の解析経路であり、CODEX-R3.md の記述と矛盾はしない。
- 備考：実 AutoHotkey v2 が括弧なし形式の `MsgBox -3` を受理するかは、ローカルに AHK 実行環境がなく未確認。少なくとも本アプリ内では受理される他形式との不整合と、誤った原因表示が欠陥。

### 観察事項（欠陥としない）
- C++ `std::cout << (unsigned char)257;`：モデルは `1` と表示する。実 g++ の出力バイトは 0x01（制御文字）。値は正しく（257 mod 256 = 1）、非印字文字の表示規約の範囲として欠陥としない。
- `(signed char)200` 等の処理系依存変換は「環境依存」で明示停止する（gcc の -56 を断定しない）。R3-F5 の裁定（符号・範囲に依存する変換は断定しない）と一貫しており、欠陥としない。
