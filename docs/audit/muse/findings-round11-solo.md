### R11-N1（P2）：C# の文字列補間が宣言なしに汎用解釈エラーで停止する

Microsoft Learn の C# チュートリアルは、値の埋め込みに一貫して文字列補間 `$"..."` を使う。本ラウンドで実行した逐語例5件――「Work with Numbers」の `$"quotient: {d}"`／`$"remainder: {e}"`、`$"The range of integers is {min} to {max}"`、`$"An example of overflow: {what}"`、「Branches and loops」の総和チャレンジ `$"The sum is {sum}"` と do-while の `$"Hello World! The counter is {counter}"`――は**全て**「エラー：式を解釈できません：$」で停止した。

C 系共通のサポート宣言（js/core/c-family.js）は、対応範囲を「単純宣言、代入、If / For / While、掲載出力」とし、未対応リストに型推論・多次元配列・動的確保・関数定義等を列挙するが、**文字列補間は対応・未対応のどちらにも記載がない**。連結（`"quotient: " + d`）は正常に動くため、壊れているのは補間だけであり、停止メッセージは未対応の宣言ですらなく汎用の解釈エラーで、学習者には「$ が書けない」という誤った原因に見える。C# の最も標準的な出力慣用形が、宣言のないまま虚偽に近い原因表示で止まるため、R9-N2（常套形が止まる＋原因表示が虚偽 → P2）の先例に倣い P2。

### R11-N3（P3）：C# の `int.MaxValue` / `int.MinValue` が「未定義の名前：int」で停止する

Learn「Work with Numbers」の範囲例の中核である `int.MaxValue`／`int.MinValue` は、補間を外しても「NameError：未定義の名前：int」で停止する。`int` は未定義の名前ではなく型名であり、型名のメンバー参照が未対応である旨の宣言もない。原因表示が虚偽のため P3（補間 R11-N1 とは別の座）。

### R11-N4（P3）：CloudFormation の `Fn::Transform` 配列形式が "undefined" をマクロ名として示して停止する

AWS 公式ドキュメント（Macro template scope の例）は `Fn::Transform` を**配列形式**（`- Name: 'AWS::Include'` のリスト）で書く。この形をモデルマクロ PolicyAdder で実行すると「未確認：モデルにマクロ定義がありません：undefined」と停止し、マクロ名の位置に内部値 `undefined` が表示される。アプリのリファレンスが示すオブジェクト形式（`{"Fn::Transform":{"Name":"PolicyAdder","Parameters":{...}}}`）は正常に動作し、Parameters の受け渡しと兄弟スコープの断片化も公式どおりだった。したがって欠陥は、(1) 公式ドキュメントの例示形式である配列形式が扱えないこと、(2) その際のメッセージが実在しないマクロ名 "undefined" を捏造して示すこと。停止自体はするので P3。

### R11-N5（P3）：AutoHotkey のユーザー関数定義が "{" を名指して停止する

公式ドキュメントの関数定義形 `Add(x, y) { return x + y }`＋呼び出しは、「未対応：この構文は説明に対応していません：{」で停止する。ユーザー関数が未対応なのは AHK のサポート宣言に明記されており範囲外自体は正直だが、名指されるのは未対応構文そのもの（関数定義）ではなく本体先頭の "{" で、R10-N5（JS の do-while が "{" を名指す）と同型の別表面のため新規 P3。

### R11-N6（P3）：ImageJ のマクロセット例で本文がそのまま実行される

公式 Macro Language の「Macro Sets」例 `macro "Macro 1" { print("This is Macro 1"); }` を実行すると、エンジンは本文をそのまま実行して「This is Macro 1」を出力する。実 ImageJ では `macro "…" { }` は**インストールされる定義**であり、実行時に本文は動かない（公式 Interpreter ソースでも MACRO トークンは skipMacro され、定義はメニュー登録される）。宣言のないまま実物と異なる振る舞いを無言で返すため P3。

### 観察（欠陥に数えないもの）

- **R の paste／numeric()／list()**：§2.6 の `paste(c("X","Y"), 1:10, sep="")`、§3.2 の `numeric()`、§6.1 の `list(...)` はいずれも「このR関数は説明に対応していません：paste」等と関数名を正しく名指して停止する。これらはアプリの宣言する R 関数集合（c、sum、mean、median、sd、length、seq、seq_len、rep、data.frame、nrow、ncol、names、is.na、as.numeric、as.character、print、cat、readline、read.csv）に含まれておらず、正直な範囲宣言として欠陥にしない。ただし paste と list は R の入門で最初に出る基本関数であり、範囲外である点自体は記録する。
- **R の `names(fruit) <- ...`**：§2.7 の名前付けは「未対応：この構文は説明に対応していません：代入先」と停止する。names の getter は宣言集合にあるが setter はなく、停止は未対応カテゴリで「代入先」という汎用名のため虚偽とまでは言えない。観察に留める。§2.7 の添字代入（`x[is.na(x)] <- 0`、`y[y < 0] <- -y[y < 0]`）は「この添字代入は未対応です」という専用の正直な宣言で停止した。
- **C# のトップレベルメソッド**（Learn の `void WorkWithIntegers() { … }` 形式）：「未対応：…：WorkWithIntegers」と、呼び出し側のメソッド名を名指して停止する。関数定義は宣言で未対応と明記されており、カテゴリも正しいため観察に留める。
- **UI.Vision の do／repeatIf と label／gotoIf**（角度4）：いずれも「このコマンドは説明に対応していません：do／label」とコマンド自体を名指して停止する。実製品では正式なコマンドだが、アプリの宣言するコマンド集合に無く、停止は正直なため観察に留める。

### 形式の一貫性（確認結果）

- 行番号は、エラーの `line` フィールドとして分離され、UI 側が「N行：」（状態欄）／「N行で停止：」（パス欄）／「LN」（トレース欄）を前置する設計（js/app.js）。**この設計に反してメッセージ本文に行番号を埋め込むのは VBA エンジン（js/engine.js）の3箇所だけ**で、うち2箇所（未終了文字列）は R9-N10 で既知、残り1箇所が本ラウンドの R11-N7。

### 代表発火（全13種類）

未定義名、0除算、未終了文字列、未対応構文、型エラーを全種類で発火させ、(line, category, message) を点検した。大半は行・カテゴリ・原因の三点が揃って正直だった（例：C# の変数経由 0 除算は「DivideByZeroException：整数の0除算です」、AHK の未対応関数は関数名を名指す、CFN の未知マクロは「未確認：モデルにマクロ定義がありません：名前」）。そこから見つかった新規は R11-N2、R11-N7、R11-N8 の3件。

### R11-N2（P2）：Power Automate の 0 除算が無言で Infinity／NaN になる

Power Automate（Desktop フローのモデル）の Set variable で `%1 / 0%` を評価すると、エラーにならず最終状態に `x=Infinity` が残る。`%1.5 / 0%` も Infinity、`%0 / 0%` と `%5 % 0%` は NaN で、いずれも無言。

実 Power Automate Desktop は .NET 意味論であり、数値の 0 除算は実行時エラーになる（クラウド式の `div(1,0)` もエラーであり、公式フォーラムでは「わざとフローを失敗させる方法」として使われるほど確立した挙動）。アプリ内の対照も明確で、VBA・Python・AHK・C 系は全て明示エラーにし、ImageJ は実物が Infinity になるため警告つきで通す（＝実物の挙動に倣う場合は断りが入る）。PA だけが、実物ではエラーになる計算を無言で JS 意味論の値に置き換えている。無言の誤値は R7-N1／R10-N3 と同格のため P2。

### R11-N7（P3）：VBA レキサの未知文字エラーで行番号が二重表示になる

VBA コードにレキサが扱えない文字（`~`、`@`）を含めると、トップエラーが「2行：2行：この構文は説明に対応していません：~」（2行目の場合）となる。js/engine.js L105 のレキサが `fail(\`${line}行：この構文は説明に対応していません：${c}\`)` とメッセージ内に行番号を含み、app.js がさらに `${line}行：` を前置するために二重化する。R9-N10（未終了文字列、engine.js L71／L83）と同根だが、発生箇所（レキサの未知文字）と表面が異なるため、取り決めどおり新規 P3 として数える。

### R11-N8（P3）：JavaScript の未対応構文の原因表示がパーサ内部の期待文・汎用エラーになる

共有パーサ（js/core/script.js）を使う JavaScript で、未対応構文の停止理由が構文そのものを指さない表面が複数確認できた：

- `a?.x`（オプショナルチェーン）と MDN 逐語例の `for (const element of array1)`（for-of。角度1で検出）が、どちらも「未対応：この構文は説明に対応していません：宣言の区切りが必要です」と、パーサ内部の期待文を名指す。
- `[...a, 3]`（スプレッド）は「エラー：式を解釈できません：.」で、未対応の宣言すらない汎用の解釈エラー（カテゴリも「エラー」）。
- `let [p, q] = [1, 2]`（分割代入）は「エラー：変数名が必要です」。
- `1 %% 2` も期待文型、`new Date(2024, 0, 15)`（角度3で検出）も「宣言の区切りが必要です」型で停止する。

いずれも学習者には「何が使えないのか」が伝わらず、特にスプレッドは括弧やピリオドが間違いであるかのような誤った原因に見える。未対応構文の名指しの失敗として1件に束ね、P3。

### 観察（欠陥に数えないもの）

- **JS の const 再代入**：「TypeError：Assignment to constant variable」は英語のままだが、V8 の実際の文言に倣った種類内一貫した流儀（R の英語の実物エラー文言と同様）とみて欠陥にしない。
- **VBA の暗黙変数**：`y = zzz + 1` が zzz=Empty として通るのは、Option Explicit のない実 VBA の挙動そのもの（暗黙宣言）で正しい。
- **VBA の On Error Resume Next**：後続の 0 除算が抑止され次の文が実行されることまで意味論が実装されていることを確認した（正しい）。

## 角度3：日付・時刻と書式化の慣用形

### 結果

日付・書式化は、対応を宣言している範囲では正確で、範囲外はほぼ全て「関数・構文を名指す正直な停止」だった：

- **VBA**：DateSerial／DateAdd／DateDiff／Format／Weekday は全て「この構文は説明に対応していません：関数 dateserial／format」と関数名を名指して停止する（宣言された範囲外）。一方 `Date` と `Now` は「実行時に決まる：実行時の現在日付／現在日時」という未確定値として正しくモデル化される。例外が R11-N9（Time）。
- **Python**：datetime はリファレンス側で supported=false と明記され、「未対応：このモジュールの読み込みは未対応です」と正直に停止する。書式化は正確：`f"{1234.5:,.2f}"` → '1,234.50'、`format(2.5, ".0f")` → '2'／`format(3.5, ".0f")` → '4'（銀行丸めまで実物どおり）、`f"{7:02d}"` → '07'。
- **JavaScript**：toFixed／padStart はメソッド名を名指して正直に停止。`new Date` は R11-N8 の期待文型で停止（同根の別表面として N8 に含めた）。
- **C#**：`v.ToString("N2")` は「この関数は説明に対応していません：v.ToString」と正直に停止。`new int[3]` は正常動作（配列はモデル化されている）。例外が R11-N10（new DateTime）。
- **R**：as.Date／format／sprintf は関数名を名指して正直に停止（宣言集合外）。
- **AutoHotkey**：FormatTime／Format は「このAutoHotkey関数は未対応です：FormatTime」と正直に停止。
- **Power Apps**：Date／DateAdd／Weekday は関数名を名指して正直に停止する。Power Fx では基本関数だが、アプリの宣言する関数集合に含まれておらず停止は正直なため観察に留める（Text の書式引数の件は R8-N5 で既知）。
- **ImageJ**：getDateAndTime は「未確認：getDateAndTime はモデルで未対応です」と正直に停止。

### R11-N9（P3）：VBA の `Time` が暗黙の変数として Empty になる

`Sub Main() / t = Time / End Sub` を実行すると、エラーにならず最終状態に `t=Empty` と、使っていないはずの変数 `time=Empty` が現れる。実 VBA の `Time` は現在時刻を返す組み込み関数であり、対照的に `Date`／`Now` は本エンジンでも「実行時に決まる」として正しく扱われている。`Time` だけが組み込みとして登録されておらず、Option Explicit のない VBA の暗黙宣言に紛れて無言で Empty になる。誤値が無言で残るため P3。

### R11-N10（P3）：C# の `new DateTime(...)` が代入先の変数名を名指して停止する

`DateTime d = new DateTime(2024, 1, 15);` は「未対応：この構文は説明に対応していません：d」と、代入先の変数名 `d` を名指して停止する。クラス生成が未対応なのは C 系宣言（動的確保・解放、複雑な型）の範囲だが、名指される対象が違う。対照的に C++ の `int* p = new int(5);` は専用の正直なメッセージ「動的確保／クラスの生成はこのモデルでは未対応です」で停止する。同じ C 系でも座により原因表示の質が分かれる表面として P3。

## 角度4：制御フローの脱出・継続バッテリー第2弾

短絡評価は、0 除算の発火・未定義名の評価・出力の有無といった観測可能な副作用で判定した。新規サンプルでの結果は、意味論そのものは全種類で実物どおりだった。

### 一致したもの

- **Python**：短絡の値意味論が正確（`0 or "x"` → 'x'、`5 and 3` → 3、`"" or 0` → 0）。副作用でも `False and f()`／`True or f()` のどちらでも f は呼ばれない（calls は空）。入れ子 break は内側だけを抜け（total=10）、早期 return で −7 を返す。
- **JavaScript**：値意味論は正確（`0 || "x"` → 'x'、`5 && 3` → 3）。関数定義が宣言範囲外のため副作用観測は代入式に切り替えたが、その代入式自体が R11-N11 で停止した。
- **C／C++**：`0 && (10 / x)`（x=0）はエラーにならず r=0、`1 && (10 / x)` は 0 除算で停止、`1 || (10 / x)` はエラーなし。短絡が実物どおり。
- **C#**：`false && (10 / x > 0)` はエラーなし、`false & (10 / x > 0)` は DivideByZeroException で停止。**`&&` と `&` の短絡／非短絡の区別まで実物どおり**にモデル化されている。
- **VBA**：`False And (1 / 0 = 0)` と `True Or (1 / 0 = 0)` のどちらでも右辺の 0 除算が発火してエラーになる。**実 VBA の「And／Or は短絡しない」が正しく再現されている**（多くの言語と逆の挙動なので特筆する）。ブロック形式 If を使った入れ子 Exit For は最内ループだけを抜けて total=3。
- **R**：`FALSE && (zzz > 0)` は未定義名 zzz を評価せず r=FALSE、`FALSE & (zzz > 0)` は NameError で停止、`TRUE || (zzz > 0)` は r=TRUE。**`&&`／`||` の短絡と `&` の両辺評価の区別が実物どおり**。`next`（合計9）と入れ子 break（total=3）も正確。
- **AutoHotkey**：`false && (10 / x)` と `true || (10 / x)`（x=0）はエラーにならず、`true && (10 / x)` は 0 除算で停止。短絡は実物どおり。入れ子 Loop の break は最内だけを抜けて total=3。
- **ImageJ**：`exit("done")` で 0,1,2 を出力して停止し後続は実行されない（実物どおり）。`break` も実物どおり動作する（公式 Interpreter ソースに BREAK／CONTINUE トークンが存在することを一次情報で確認し、当初の「実物には break がない」という想定を**取り消した**）。
- **Power Apps**：`If(false, Set(x, 1), Set(x, 2))` で x=2（選ばれた分岐だけが評価される分岐隔離が正しい）。Switch も正確。
- **Power Automate**：入れ子 Loop＋If＋Exit loop で最内ループだけを抜け Total=3。条件の等値はアプリ自身の記法である `==`（テンプレートの `%Answer% == "はい"` 等）で書くのが前提で、`=` と書くと「未対応：…：=」で停止する点はアプリ内の記法一貫性の観察に留める。

### R11-N11（P3）：代入式を被演算子位置で使う形が「) が必要です」で停止する

`int r = 0 && (x = 5);`（C）、`1 || (x = 7)` 型（C++）、`bool r = false && (x = 5) > 0;`（C#）、`let r = false && (x = 5);`（JavaScript）のいずれも、「エラー：) が必要です」で停止する。C では初期化子単独の `int r = (x = 5);` でも同じ。括弧の対応は取れており、原因は虚偽。4言語とも代入は式であり、条件内代入（`while ((x = next()) != …)` 等）は中心的な慣用形の前提になる。パーサは JS（js/core/script.js）と C 系（js/core/c-family.js）で別だが、同じ文言・同じ型の失敗が両方に出る横断表面として1件に束ね、P3。

### 観察（欠陥に数えないもの）

- **VBA のユーザー Function プロシージャ**：宣言が「単一Sub」であり、Function プロシージャは範囲外。配置によって「この構文は説明に対応していません：Function F ( ) As Boolean」（関数ヘッダを名指す）か「End Sub の後に実行文は置けません」（Sub の後に Function を置いた場合）になる。後者は実 VBA では正常な配置への誤解を招く文言だが、複数プロシージャ自体が宣言範囲外のため観察に留める。これにより VBA の短絡（非短絡）は関数ではなく 0 除算の発火で観測した。
- **VBA の1行 If**：「1行形式の If（複数行形式を使用してください）」という、構文名と代替手段を示す模範的に正直な宣言で停止する（宣言にも明記）。
- **R のユーザー関数と `<<-`**：関数定義自体が宣言集合外（「このR関数は説明に対応していません：function」）、`<<-` も未対応宣言で停止する。短絡の観測は未定義名の評価有無に切り替えて実施し、結果は実物どおりだった。
- **JS のラベル**：ラベル付き break／continue（MDN 逐語例含む）は「未対応：…：:」とコロンを名指して停止する。ラベルは宣言範囲（If／For／While）に無く、カテゴリは正しいため観察に留める。
