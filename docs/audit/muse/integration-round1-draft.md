## (b) 未解決の論点

1. **INT-01（confirm）の重大度と扱い**：コード事実に争いはない（6b85ac4 でも未変更、発火条件は「エディタ内容 ≠ 選択テンプレートのコード」で、未編集のテンプレート間切替を含む）。評価の相違は検証環境の差に由来するとみられる。Codex の「テンプレート入口176操作合格」はローカルブラウザでの結果で、CODEX-R1 にはダイアログの扱い（受理したか）が明記されていない。Muse 角度C は公開サイトでダイアログを通過できず全経路で切替不可だった。人間の利用者には「毎回ダイアログが出る」こと自体が中核操作への恒常的な摩擦であり、ダイアログを抑制する埋め込み環境等では切替不能になる。要件正本には上書き確認の要件はなく、裁定（未編集時は無確認／編集済み時のみ保護する等）が必要。
2. **「実行できるコード」の基準差**：CX16 の使用例「380例すべて実行しエラーなし」はアプリ内シミュレータでの実行が基準。Muse 側の INT-04／INT-05／INT-15 は実コンパイラ（gcc／g++）基準で不適合。テンプレートとリファレンス使用例は学習者が実環境へ持ち込む教材であり、どちらの基準で収束判定するかが裁定事項（Muse 側は実物基準を推す）。
3. **公開サイトの直接確認が双方未了**：Codex も CODEX-R1 残件2で「公開サイトの直接取得・実ブラウザ操作は未確認」と明記（HTTP 許可先の制約）。6b85ac4 の GitHub Pages 反映と公開サイトでの INT-01 等の挙動確認は未実施。ローカルの合格を公開の合格に読み替えない。
4. **一次情報の全件照合が双方未完**：Codex は「全441リファレンスの説明文・戻り値・注意点の全件照合は未実施」、Muse 側も角度A で VBA 66件の公式文面照合、R 23件の使用例実行、ImageJ 細部4点、Python 用語集34件の残りが未確認。第2ラウンドの対象として双方一致。
5. **要件正本の版のずれ**：Codex の対応表（REQUIREMENTS.md）は書き直し前の旧正本（旧 §番号、37項目）に対するもの。書き直し後の新正本では章立てが変わっている（対応付けは (d) 節）。内容の実質は同一だが、次節目以降の対応表は新正本の番号で作る必要がある。また新正本 §11（履歴）の「分岐100は普通にありえる」は旧い考え方の経緯記録であり、現行要件は §4 の上限2,000件。Codex 対応表の 1.3-7／4-4 が旧表現を現行要件のように引用している点は、履歴として読むのが正しい。
6. **INT-17（NameError 分類）の露出範囲**：TDZ の表示は是正されたが、共有エンジンの未定義名エラー分類 "NameError" は JS でも残っている。UI 上で分類文字列が学習者に見える経路があるかは公開サイト側の確認待ち。
7. **角度C で未確認だった 375px・ファイル読込・オフライン**：Codex はローカル 728 ケースに含めて合格と申告しているが、Muse 側の独立再確認は未実施。第2ラウンドで Muse 側もローカル Playwright（実績あり）で再確認できる。
