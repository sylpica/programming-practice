## 統合台帳

### RG-01 共有実行器の深さ上限（64）によるパスの無言欠落
- 根本原因：else-if 連鎖が otherwise 内の入れ子 if として実行され、深さ上限（LIMITS.depth=64）を1条件ごとに消費する。上限超過はパス内のエラーに変換されるため、`truncated`／`reasons` に記録されず、打ち切りの告知なしにパスが欠落する。平坦な連鎖に対して「ブロックの入れ子が深すぎます」と表示される点も原因表示として誤り。
- 重大度：**P2**
- 統合元：R4-N1（findings-round4-solo.md、JavaScript／R／AutoHotkey）、R5-N1（findings-round5-solo.md、C#／c-family 経路）
- 影響する種類・表面：共有スクリプトエンジン（JavaScript／R／AutoHotkey）と C#。65条件以上の else-if 連鎖、深さ64超の入れ子。C／C++ は未知条件を作る手段がなく再現しないことを確認済み。
- 修正方針：else-if を深さを消費しない形で実行する、または深さ超過を打ち切りとして `truncated`＋`reasons` に必ず記録し、パス見出し・バナーで告知する。連鎖に対する文言は実態（連鎖の長さ）に合わせる。
- 受け入れ条件：65条件の else-if（JS／R／AHK／C#）と70段入れ子で、全パスが列挙されるか、欠落が告知されること。64条件まで完全だった既存挙動と、VBA／Python の正挙動に回帰がないこと。

### RG-02 0除算・特殊値の無言の JS 意味論化（Power Apps／Power Automate）
- 根本原因：0除算や特殊値を JavaScript 意味論（Infinity／NaN）で処理し、実物の意味論（Power Fx ではエラー値、Power Automate Desktop では .NET の実行時エラー）に合わせていない。表面によっては表示と最終状態が矛盾する。
- 重大度：**P2**
- 統合元：R11-N2（findings-round11-solo.md、Power Automate：全形式で無言 Infinity／NaN）、R7-N9（findings-round7-solo.md、Power Fx：Notify 表示 "Infinity" と最終状態 null の矛盾）、R12-N27（findings-round12-solo.md、Power Fx：Set に文字列 "Infinity"／"NaN" が格納される。R7-N9 と同根の別表面）
- 影響する種類・表面：Power Apps（表示・変数格納）、Power Automate（式の評価全般）。
- 修正方針：種類ごとの実物意味論に合わせ、0除算は明示エラー（またはエラー値）として、表示・trace・最終状態で一貫させる。ImageJ のように実物が Infinity の種類の扱いとは分離すること。
- 受け入れ条件：`1/0`、`0/0`、`5 % 0` 等の全形式で、実物どおりのエラーになるか、エラー値として全表面が一致すること。

### RG-03 R の NULL の意味論の欠落（長さ0でなく 0 として扱う）
- 根本原因：R エンジンが NULL を長さ1の値 0 として保持し、長さ0オブジェクトとしての意味論を持たないため、算術・比較・関数が誤った値を返す。
- 重大度：**P2**
- 統合元：R7-N1（findings-round7-solo.md、`NULL + 1` → c(1) 等の誤値捏造）、R8-N7（findings-round8-solo.md、`is.na(NULL)` が FALSE を返す。実 R は logical(0)）
- 影響する種類・表面：R の NULL が絡む全演算・関数。表示面の同根表面は RG-04（R5-N6）。
- 修正方針：NULL を長さ0の値として実装し、演算は長さ0を返し、`is.na(NULL)` は logical(0) を返すよう意味論を実 R に合わせる。
- 受け入れ条件：`NULL + 1`、`NULL == NULL`、`length(NULL + 1)`、`is.na(NULL)` が実 R と一致すること。NA の伝播や `c(1, NULL)` の既存の正挙動に回帰がないこと。

### RG-44 AutoHotkey のバッククォートエスケープの変換漏れ（制御文字が文字そのものに化ける）
- 根本原因：共有トークナイザの AutoHotkey エスケープ処理が `` `n ``／`` `r ``／`` `t `` 等の一部だけを変換し、それ以外は「文字そのもの」を返すフォールバックになっているため、公式の制御文字エスケープ `` `a ``／`` `b ``／`` `f ``／`` `v `` が、エラーにならず無言で文字 'a'／'b'／'f'／'v' に化ける。
- 重大度：P3

- 受け入れ条件：公式エスケープ全件が実 AutoHotkey v2 と一致すること。変換済みの `` `n ``／`` `t `` 等の正挙動に回帰がないこと。

### RG-45 R の NaN が比較・論理演算で NA にならない（JS 意味論の真偽を返す）
- 根本原因：R エンジンの二項演算が NA オブジェクトだけを欠損として先行処理し、数値 NaN は baseBinary の JavaScript 意味論（NaN の比較は false、!= は true）に落ちる。実 R では NaN は比較・論理演算で NA として扱われる。算術での NaN の伝播自体は正しい。
- 重大度：**P2**
- 統合元：R15-N11（findings-round15-solo.md、`(0/0) == (0/0)` が c(FALSE)、`(0/0) != 1` が c(TRUE)、`(0/0) & TRUE` が c(FALSE) 等。公式 Relational Operators の「comparisons involving NaN will always result in NA」と相違する）
- 影響する種類・表面：R の NaN が絡む比較演算子・論理演算子全般（条件分岐の材料になる）。
- 修正方針：R の二項演算で NaN を NA と同格に先行処理し、比較・論理の結果を NA にする（RG-03 の NULL の意味論とは別経路だが、欠損値の扱いとして一貫させること）。
- 受け入れ条件：再現の全ての比較・論理式が実 R どおり NA を返すこと。NaN の算術伝播と通常値の比較の正挙動に回帰がないこと。
- 処置結果（2026-11-15 Muse 修正・第1バッチ）：**実装**（末尾「RG-01〜RG-48 の処置一覧」の RG-45 の行に集約記録。要点：R の NaN の欠測扱い）。

### RG-46 Python の等価判定の同一性ショートカット（NaN の自己比較が True になる）
- 根本原因：Python エンジンの eqVal が「同じオブジェクト同士は等しい」と同一性で先行判定し、float の NaN にも適用される。CPython の == は同一オブジェクトでも値比較であり、NaN は自分自身とも等しくない（`in` の同一性規則とは別の話で、そちらは現状どおり正しい）。
- 重大度：P3
- 統合元：R15-N12（findings-round15-solo.md、`n = float("nan")` の後に `n == n` が True、`n != n` が False、`n <= n` が True になる。いずれも実 CPython と逆）
- 影響する種類・表面：Python の ==／!=／<=／>= 等の比較（同一変数を両辺に置く自己比較で表面化する）。
- 修正方針：浮動小数の比較から同一性ショートカットを外し、値比較（NaN は非等価）にする。`in` の同一性規則には触れない。
- 受け入れ条件：再現の自己比較が実 CPython と一致すること。通常値の等価判定と `n in [n]` の正挙動に回帰がないこと。
- 処置結果（2026-11-15 Muse 修正・第1バッチ）：**実装**（末尾「RG-01〜RG-48 の処置一覧」の RG-46 の行に集約記録。要点：Python の NaN 自己比較（コンテナ同一性は意図的に保持））。

### RG-47 R のデータフレームに対する `[[` の意味論の欠落（列ベクトルでなくデータフレームを返す）
- 根本原因：R エンジンの index 読み取りで、データフレーム分岐が `a.double`（[[ かどうか）を見ずに、列選択のデータフレーム構築へ進む。ベクトルに対する [[ は正しく要素を返すため、壊れているのはデータフレーム分岐だけ。
- 重大度：**P2**
- 統合元：R15-N14（findings-round15-solo.md、`df[["x"]]` が "x: c(1, 2)" のデータフレーム表示になり、単一括弧 `df["x"]` と表示が完全に同一化する。下流では `mean(df[["x"]])` が虚偽の型エラー、`df[["x"]] + 10` が c(NaN) の無言の誤値になる）
- 影響する種類・表面：R のデータフレームの添字操作全般（R 教材の中核操作）。
- 修正方針：データフレーム分岐で [[ と [ を区別し、[[ は列ベクトル（要素）を取り出す実 R の意味論にする。数値添字 `df[[1]]` も同様に扱う。
- 受け入れ条件：`df[["x"]]` と `df[[1]]` が列ベクトルを返すこと。`df["x"]`（データフレームを返す）の正挙動と、ベクトルの [[ の正挙動に回帰がないこと。下流の演算・関数適用が実 R と一致すること。
- 処置結果（2026-11-15 Muse 修正・第1バッチ）：**実装**（末尾「RG-01〜RG-48 の処置一覧」の RG-47 の行に集約記録。要点：R の `df[[列]]` 列取り出し）。

### RG-48 AutoHotkey のメンバー解決の大文字小文字（`.Length` が停止し `.length` だけが通る）
- 根本原因：共有実行器のメンバー読み取りが `length` の完全一致（小文字）でのみ配列長・文字列長を返し、AutoHotkey 側のメンバー解決に大文字小文字の正規化がない。実 AutoHotkey v2 ではプロパティ名は大文字小文字を区別しない。制御キーワードの照合（RG-32）とは別の機構（実行器のメンバー解決）である。
- 重大度：P3
- 統合元：R15-N16（findings-round15-solo.md、`a.Length` が「プロパティがありません：Length」で停止し、`a.length` は 3 を返す。文字列の `.Length` も同型）
- 影響する種類・表面：AutoHotkey の組み込みプロパティ参照全般（配列・文字列の Length）。
- 修正方針：AutoHotkey のメンバー解決で名前を大文字小文字不区別に照合する（言語仕様どおり）。他種類の大文字小文字を区別する解決に波及させない。
- 受け入れ条件：`.Length`／`.length`／混在表記がいずれも実 AutoHotkey v2 どおりに動作すること。存在しないプロパティへの正直な停止に回帰がないこと。
- 処置結果（2026-11-15 Muse 修正・第1バッチ）：**実装**（末尾「RG-01〜RG-48 の処置一覧」の RG-48 の行に集約記録。要点：AHK メンバ名の大小不区別）。

### 保留・未確定（理由つき）

1. **RG-12 の Power Fx 部分**：暗黙の Text↔Number 変換と `=` の変換・大小規則は、Microsoft Learn の一次資料が定義せず、二次資料が矛盾する。実ランタイムでの確認が取れるまで現行挙動を維持する。
2. **RG-04 の R 表示2点**：空ベクトルの `numeric(0)` 等の表記は要素型を持つ空ベクトルが値モデルに無く、既存テストも `c()` を固定。長さ1の表記ゆれも既存テストが両側を固定。3表面内では矛盾しない。
3. **Power Fx の `Blank() = 0`／`Blank() = ""`（198件に不算入の未確定候補）**：Learn は算術演算での 0 への強制のみを述べ、等値比較は未定義。IsBlank の解説は `Value = Blank()` が空文字列と区別されることは支持するが 0 については確定できない。DAX の規則は別言語のため転用しない。現行挙動（両方とも偽）は変更しない。
4. **RG-37 の実ブラウザ実測**と **RG-57 の実ブラウザフロー確認**：構造とロジックは実装・単体検証済み。実ブラウザでの実測は親工程の検証項目。
