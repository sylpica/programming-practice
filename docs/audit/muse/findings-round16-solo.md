## 角度1：演算子の優先順位・結合性（242プローブ）

### R16-N1（P2・新規）C系（C／C++／C#）の共有優先順位表が C 標準と相違し誤値
`prec` 表で `^`（10段）が `&`（3段）より上、`|`（2段）が `&&`（2段）と同位。実 C では `&` ＞ `^` ＞ `|` ＞ `&&` の順。誤値の表面（全数洗い済み）：
- C：`6 & 3 ^ 5` → 6（実 7）、`1 ^ 3 & 2` → 2（実 3）、`2 ^ 3 & 1` → 1（実 3）、`12 & 10 ^ 5` → 12（実 13）、`0 && 1 | 1` → 1（実 0）
- C++：`12 & 10 ^ 5` → 12（実 13）、`0 && 1 | 1` → 1（実 0）
- C#：`2 ^ 3 & 1` → 1（実 3）、`6 & 3 ^ 5` → 6（実 7）
対照：JavaScript は別表 `jsPrec` で `& ^ |` の順序が正しく、同プローブは全て正解。

### R16-N2（P2・新規）C# の bool に対する `&` `|` `^` が全位置で虚偽原因の停止
再現：`bool b = true & false;`、`Console.WriteLine(true | false);`、`if (true ^ false) { }`、bool 変数同士 — いずれも「演算する型が一致しません」で停止。実 C# は bool に3演算子とも定義する（`&&`／`||` と int の `&` はエンジンでも正常）。第11ラウンドの類似プローブは 0 除算が型検査より先に発生して本件をマスクしていた（割る数を 2 に変えると本件が露出することを再確認済み）。

### R16-N3（P2・新規）R の特殊演算子 `%%` `%/%` が `*` `/` と同位
実 R では `%任意%` は `*` `/` より上位。誤値：`2 * 5 %% 3` → 1（実 4）、`10 %% 3 * 2` → 2（実 4）、`2 * 5 %/% 3` → 3（実 2）、`10 %/% 3 * 2` → 6（実 1）。`+` との関係（上位で正）と `^` との関係（下位で正）は正常。`%in%` は名前を挙げた正直な未対応停止のため対象外。

### R16-N4（P2・新規）R の `|` が `&&` と同位
実 R では `&`／`&&` の段が `|`／`||` の段より上。誤値：`TRUE | TRUE && FALSE` → FALSE（実 TRUE）、`TRUE | FALSE && FALSE` → FALSE（実 TRUE）。`&` 対 `|`、`||` 対 `&&` の組は正常。

### R16-N5（P2・新規）R の `!` が比較より上位
実 R の `!` は比較より下（`&` より上）。誤値：`!1 == 2` → FALSE（実 TRUE）、`!1 < 2` → TRUE（実 FALSE）。

### R16-N6（P2・新規）AHK の単語演算子 `not` が `!` と同じ高さ
公式 AHK v2 の NOT は比較より下位。誤値：`(not 1 = 2) * 5` → 0（実 5）、`(not 1 < 2) * 5` → 5（実 0）。記号形 `!` の段付け自体は公式どおり。

### R16-N7（P3・新規）Power Fx の公式綴り `And`／`Or`／`Not` が虚偽原因で停止
`1 < 2 And 2 < 3`、`false Or true`、`1 < 2 AND 2 < 3` が「) が必要です」で停止、`Not(false)` が「このPower Fx関数は説明に対応していません：Not」で停止。小文字 `and`／`or`／`not(...)` と `&&`／`||` は正常動作する。キーワード照合が大文字小文字を区別することが根。（Power Fx の `in` の虚偽原因は第8ラウンド既知のため除外。）

### R16-N8（P2・新規）Power Fx の `%` 後置演算子（50% = 0.5）が未実装で誤値・虚偽原因
- `50% + 1` → **無警告で 0**（実 1.5）
- `Set(R, 50%)`、`(50%)` → 「式を解釈できません：)」
- `25% * 200`、`50% * 200` → `*` を名指して停止（実 50／100）
- `200 - 50%` → 「式を解釈できません：)」（実 199.5）
対照 `0.5` リテラルは正常。百分率は Power Fx の基本記法であり、無警告の誤値を含むため P2。

### R16-N9（P3・新規）JavaScript のシフト演算子 `<<` `>>` `>>>` が全位置で停止
トークン化はされるが `jsPrec` に段が無い。宣言・代入位置では汎用文言、関数引数位置では「) が必要です」、配列位置では「] が必要です」の虚偽原因になる。

### R16-N10（P3・新規・R12-N13 の同根別表面）C系シフトが printf 引数位置で虚偽原因
`printf("%d\n", 1 << 3);` が「) が必要です」で停止。宣言位置の汎用停止は R12-N13 で既知だが、引数位置の虚偽原因は別表面として記録する。

### 角度1で棄却・観察に留めたもの
- VBA `2 ^ 3 ^ 2` = 512 は**正しい**（VBA の `^` は右結合。Excel の左結合 64 とは異なる）。初期仮説を一次資料で棄却。
- Power Fx `2 ^ 3 ^ 2` → 512 は観察のみ（Power Fx 公式は `^` の結合性を定めていない）。
- AHK `**` は最初の `*` のみを名指して停止（アプリのリファレンス未掲載のため観察）。AHK の連結 `.` の段付け、`1 + 2. 3` = "33" は公式どおり正解。
- Python 22件・ImageJ 6件の優先順位プローブは全てオラクル一致。VBA の And／Or／Xor の段付けは正常。

## 角度2：Unicode・日本語文字列（83プローブ）

到達可能な意味論は全て実物どおりだった：Python（コードポイント単位の len／添字／スライス、`"ß".upper()` = "SS"、結合文字の ord = 12441）、JS（`.length` の UTF-16 単位×4、サロゲート半分の `.length` = 1、半分同士の不一致）、VBA（Len の UTF-16 単位×4、Mid の単位位置で Mid(B,3,1) = 野・Mid(B,4,1) = 家、Left との合成）、ImageJ（lengthOf、substring(0,2) がアストラル文字を丸ごと返す）。C の char 文字列は「ASCII に限定」と明示宣言されており宣言範囲外として正直。大半の文字列関数は名前を挙げた正直な未対応停止（JS の charCodeAt 等、C# の Substring 等）。

### R16-N11（P3・新規・R12-N16 の同根別表面）C# 文字列の添字 `s[i]` が虚偽原因で停止
`Console.WriteLine((int)s[0]);`（リテラル形・変数形とも）が「) が必要です」で停止。実 C# では文字列の添字アクセスは基本機能。`.Length` の停止（R12-N16）と同根の別表面。

### R16-N12（P3・新規）AHK の真偽結果の表示が 1／0 でなく true／false
`MsgBox 1 = 1` が "true"（実 AHK v2 は "1"）、最終状態でも `x = true` と表示される。内部値は 1 として正しく計算される（`(1 = 1) + 1` = 2）ため表示のみの問題。他言語の真偽表示既知件（R5-N4／N7）と同種。

なお本角度の検証文字は意図した U+20BB7 でなく見た目の似た U+10BB7（コードポイント 68535）が混入していたが、長さ・添字の意味論には影響しない（サロゲートペアであることは同一）。

## 角度3：オーバーフローと除算の境界（62プローブ）

オラクル：CPython 3.12.3、Node v24.22.1、C# は言語仕様。宣言モデルの範囲内では誤値は出なかった：Python の巨大整数は「実行時に決まる：とても大きな整数・この説明では正確に計算しません」と明示して未知化され（2^53 境界の内外で誤数値が出ないことを確認、範囲内は 1e6×1e6 = 1000000000000 等で正確）、C の int の `+` `*` `+=`・INT_MIN / -1 は宣言どおり未定義動作として停止、C# の int ラップ値（1000000×1000000 → −727379968 等）と MinValue / -1 の OverflowException、ゼロ除算の DivideByZeroException は仕様どおり。

### R16-N13（P2・新規）C系で 2^53 超のリテラルが式の位置では丸め誤値を無警告で表示
- C++：`std::cout << 9007199254740993L` → **9007199254740992**、`std::cout << 9223372036854775807L` → **9223372036854776000**、`(9223372036854775807L - 9223372036854775806L)` → **0**（実 1）
- C：`printf("%d", (int)(9223372036854775807L - 9223372036854775806L))` → **0**（実 1）
一方、変数宣言経由（C／C++／C# とも）と C# の全形は「安全に計算できる範囲外」で正直に停止する。安全範囲ガードが宣言経路と一部の演算結果にしか効いておらず、リテラルの語彙解析（JS Number 化）の丸めが式の位置で素通りすることが根。LLONG_MAX は long の教材で必ず現れる境界値であり無警告の誤値のため P2。

### R16-N14（P3・新規）C# の `int.MinValue % -1` が OverflowException で停止
実 C# では `MinValue % -1` は 0 で正常終了する（例外になるのは `/` のみ）。エンジンは除算オーバーフローの検査で `/` と `%` を一括扱いするため誤って例外になる。long 形は「未確認：64ビット精度の上限です」で停止（兄弟表面・原因も不正確）。

### R16-N15（P3・新規）C系の ++／-- の溢れが方言別の二項演算規則を経由しない
- C#：`int x = 2147483647; x++;` が OverflowException で停止（実 C# の unchecked 既定では −2147483648 にラップ）。`x--`（MinValue）も同様。
- C／C++：`x++`／`x--` の溢れが「環境依存：整数への変換結果は処理系依存です」で停止するが、実態は未定義動作であり、二項・複合代入の溢れは正しく「符号付き整数のオーバーフロー」として停止する。分類の誤り。
R12-N11（前置 ++x の汎用停止）とは別表面。

### R16-N16（P3・新規）JavaScript の BigInt リテラル `10n` が虚偽原因で停止
`console.log(10n * 3n);` が「) が必要です」で停止。`n` 接尾辞の語彙解析が無く、原因も虚偽。

### 角度3で観察に留めたもの
- C の LONG_MIN / -1、C# の long 境界各種は「未確認」で停止（原因の精密さは劣るが誤値なし）。
- C の `unsigned` 型・`short` は宣言部分集合外として停止（`short` の原因文が変数名を名指す奇妙さは観察）。
- R の `5 %/% 0` の値 Inf 自体は正しい（表示 "Infinity" は既知 R7 系）。AHK の int64 境界は「範囲外」で正直に停止（公式でもオーバーフローは未定義のため観察）。VBA `32767 + 1` のオーバーフロー停止は宣言モデル範囲（第12ラウンドの先例どおり不算入）。ImageJ の Inf 表示は実物どおり。
