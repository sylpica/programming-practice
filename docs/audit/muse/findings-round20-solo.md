## 角度1：未初期化と初期値の意味論（51プローブ → 新規2件）

正しかった表面（抜粋）：

- VBA：`Dim` の既定値が全て実物どおり（Long／Double は 0、String は `""`（Len=0）、Boolean は False、Variant は Empty で `IsEmpty` が True、静的配列の要素は 0、初期値での計算も正）。未宣言名の読みは Option Explicit なしの実 VBA どおり暗黙 Variant（Empty）になるため欠陥に数えない。
- Python／R／ImageJ／AutoHotkey／Power Automate／UI.Vision：未定義・未代入の読み取りは全て名前を挙げた正直なエラーで停止（ImageJ の「変数 x は、まだ値が代入されていません」を含む）。
- JavaScript：`let` 無代入は `undefined`、`var` 無代入の `+1` は `NaN`、未宣言名は ReferenceError、TDZ（初期化前の `let` 参照）は専用メッセージ、`var` の巻き上げ読みは `undefined` と、全て実物どおり。
- C／C++：未初期化の読み取り（変数・配列要素・char）は全てアプリの宣言モデルどおり「未定義動作：未初期化の値を読み取っています」で停止し、具体値を捏造しない。
- C#：未代入ローカルの読み取り（値位置・条件位置・string／bool）は全て `CompileError：未割り当てのローカル変数です` で停止し、`new int[2]` の要素既定値 0 は正しく返る（実 C# の確定代入規則どおり）。
- Power Fx：未定義名は NameError で停止。`Set(x, Blank())` 後の表示が `null` になる点は RG-04 の既知表面のため数えない。

### R20-N1（P2・新規／RG-40 の新規表面）C++ の既定構築 `std::string` が「未初期化」と誤判定され、読み取り全般が未定義動作で停止する

- 再現：`std::string s;` の後に読み取ると全て「未定義動作：未初期化の値を読み取っています」で停止する。確認した表面は4つ：`std::cout << "[" << s << "]"`、`s + "cd"`、`s == ""`、`s += "x"`（代入 `s = "ab"` を先に行えば回復する。コピー初期化 `std::string s = "";` は正常に動作し `[]` を出力する）。
- 実物：既定構築された `std::string` は空文字列として完全に初期化されており、全ての読み取りが有効（g++ の通常意味論）。
- 根本原因：RG-40 と同根。文字列モデルが「宣言時に初期化子があったか」で初期化状態を追跡しており、既定構築（初期化子なし）を未初期化として記録する。統合元 R14-N3 の2表面（添字参照・直接初期化）には無い再現表面のため、新規の元項目として RG-40 に帰属させる。
- 受け入れ条件の目安：`std::string s;` の後の出力・連結・比較・`+=` が空文字列として実 C++ と一致し、未初期化のスカラ変数の UB 判定には回帰がないこと。

### R20-N2（P3・新規／RG-06 の新規表面）C／C++ の `static` 変数が、無関係なトークン `int` を名指して未対応停止する

- 再現：`static int x; printf("%d\n", x);`（C／C++ とも）が `未対応：この構文は説明に対応していません：int` で停止する。`static int x; x = 3;` と代入してから読んでも同じ停止。
- 実物：`static` 変数は 0 に初期化され、読み取り可能（C／C++ の静的記憶域期間の基本規則）。
- 根本原因：RG-06 と同根。`static` を構文として認識せず、後続の型名トークン `int` を対象として表示する（`int` 自体は対応済みであり、原因表示として誤り）。値の捏造はないが、「何が未対応なのか」を学習者に誤って伝える。
- 受け入れ条件の目安：`static` 変数が 0 初期化で動作するか、対象として `static` を名指した未対応宣言で停止すること。

## 角度2：条件位置の truthy／falsy 全表（108プローブ → 新規5件）

正しかった表面（抜粋）：

- Python（15件：`0`／`0.0`／`""`／`[]`／`{}`／`None` が偽、`"0"`／`"false"`／`[0]` が真）、JavaScript（12件：`[]`／`{}` が真、`NaN`／`null`／未代入変数が偽）、C（7件：`"x"` のポインタ真を含む）、C#（5件：bool 以外は全て「C#の条件にはboolが必要です」で正直に停止）は全て実物どおり。
- VBA の数値・数値文字列・Empty は実物どおり（`"5"`／`"-1"` は真、`"0"` は偽、`""`／`"hello"` は型エラーで実 VBA の変換規則と一致）。
- R（波括弧形式の12件）：数値の真偽変換、`NA` の "missing value where TRUE/FALSE needed"、`""`／`"TRUE"` の "argument is not interpretable as logical"、長さ2条件の "the condition has length > 1"、`c()` の "argument is of length zero" は全て実 R（Rscript 照合）と一致。
- AutoHotkey の数値・空文字列・`"false"`／`"x"` は v2 公式どおり（下記 N3 の数値文字列だけが外れる）。
- Power Fx の数値（0→偽、非0→真）と `""`→偽、`Blank()`→偽は、Learn の変換規則（空テキストは Blank になり、If では偽として扱われる）と整合するため欠陥に数えない。

### R20-N3（P2・新規／新規群 RG-73相当）AutoHotkey の条件位置で数値文字列 `"0"`／`"0.0"`／`"00"` が真になる

- 一次情報：AutoHotkey v2 公式ドキュメント If ページの Remarks — "evaluates to true (which is any result other than an empty string or the number 0)"。数値文字列は数値として解釈されるため `"0"` は「数値 0」として偽になるのが v2 の仕様（v1 との相違点として知られる規則）。
- 再現：`if "0"`、`if "0.0"`、`if "00"` のいずれもアプリは真（T）分岐に入る。実 v2 では全て偽。`"2"` が真になる点はアプリも正しい（数値解釈そのものは行われておらず、非空文字列＝真で処理されていると見られる）。
- 影響：入力ダイアログ等で得た文字列 `"0"` をそのまま条件に使う教材頻出パターンで、分岐が無言で逆になる。
- 受け入れ条件の目安：数値文字列の真偽が数値解釈どおり（0 相当は偽、それ以外は真）になり、`""`／`"false"`／`"x"` の既存の正挙動に回帰がないこと。

### R20-N4（P3・新規／新規群 RG-74相当）VBA の条件位置で `"True"`／`"False"` 文字列が型エラーになる

- 再現：`If "True" Then`、`If "true" Then`、`If "False" Then` が全て「型が一致しません」で停止する。
- 実物：VBA の条件変換（CBool と同じ規則）では、文字列 `"True"`／`"False"` は大小無区別で真偽値に変換され、エラーにならない。アプリは数値文字列（`"5"`→真、`"0"`→偽、`"-1"`→真）は正しく変換するのに、真偽リテラル文字列だけ変換表に無い。
- なお `CBool` 関数自体はアプリ未対応（構文名を挙げた正直な停止）であり、本件とは別に数えない。
- 受け入れ条件の目安：`If "True"`／`If "False"`（大小の別を含む）が実 VBA どおり分岐し、`""`／`"hello"` の型エラーには回帰がないこと。

### R20-N5（P3・新規／新規群 RG-75相当）Power Fx の条件位置で変換不能なテキストが無言で真になる

- 一次情報：Microsoft Learn「Boolean function」— テキストから Boolean への変換は大小無区別の `"true"`／`"false"` のみで、空テキストは Blank、それ以外のテキストは**エラー**を返す。自動型強制も同じ規則（同ページの例 `If( "true", 1, 0 )` は 1 を返す）。
- 再現：`Notify(If("0", "T", "F"))` → アプリは "T"、`Notify(If("hello", "T", "F"))` → アプリは "T"。実 Power Fx ではどちらも変換エラーになる。アプリは JS の truthiness（非空文字列＝真）を流用していると見られる。
- 受け入れ条件の目安：`"true"`／`"false"` 以外のテキスト条件が、名前を挙げた変換エラーとして停止し、`"true"` の自動変換と数値条件の既存挙動に回帰がないこと。

### R20-N6（P3・新規／新規群 RG-76相当）C++ の条件位置で `std::string` が内容依存の truthy になる

- 再現：`std::string s = "x"; if (s) {...}` → アプリは真分岐、`s = ""` では偽分岐。内容によって真偽が変わる JS 意味論になっている。
- 実物：`std::string` には bool への文脈変換がなく、`if (s)` はコンパイルエラー（g++："could not convert 's' from 'std::string' to 'bool'" 相当）。C の `if ("x")`（ポインタ＝真）がアプリで正しく真になるのとは対照的に、C++ のクラス型までスカラと同じ truthiness で処理されている。
- 根本原因：C系の条件評価が型検査をスカラ（数値・ポインタ）に限らず、文字列オブジェクトへも truthiness を適用している。
- 受け入れ条件の目安：C++ で `std::string` を条件に置くと型エラーを名指して停止し、C の文字列リテラル条件（ポインタ）には回帰がないこと。

### R20-N7（P3・新規／RG-03 の新規表面）R の `if (NULL)` が無言で FALSE になる

- 再現：`if (NULL) { print("T") } else { print("F") }` → アプリは "F" を返す。同じ長さ0でも `if (c())` は "argument is of length zero" で正しくエラーになるため、NULL だけが素通りする。
- 実物：Rscript 照合で `if (NULL)` は "argument is of length zero" エラー（`logical(0)` も同じ）。
- 根本原因：RG-03 と同根。NULL を長さ1の値 0 として保持するため、条件評価では数値 0（＝FALSE）として処理され、長さ0の検査をすり抜ける。統合元（算術 `NULL + 1`、`is.na(NULL)`）には無い条件位置の表面のため、新規の元項目として RG-03 に帰属させる。
- 受け入れ条件の目安：`if (NULL)`／`while (NULL)` が実 R どおり長さ0のエラーになり、`c()` の既存の正挙動に回帰がないこと。

### 撤回した仮説：ImageJ の条件 0/1 制限は欠陥ではない

- 当初の観察：`if (-1)`、`if (0.5)`、`if (2)`、`while` のカウントダウン等が「条件が 0 か 1 になっていません」で停止するため、「実 ImageJ は 0 以外を真とするはず」という仮説を立てた。
- 一次情報による裁定：公式ソース `ij/macro/Interpreter.java` の `getBoolean()` は条件評価後に `checkBoolean(value)` を呼び、値が 0.0／1.0 以外なら "Boolean expression expected" エラーにする。`&&`／`||`／`!` の被演算子にも同じ検査がかかる。**アプリの制限は実物の仕様どおり**であり、仮説は誤りだったため撤回する。
- なお同ソースで、三項演算子の条件だけは `checkBoolean` を通さず「0以外は真」（ソース内コメント "ImageJ macro treats non-zero as true"）であり、アプリも `2 ? 10 : 20` → 10、`-1 ? 10 : 20` → 10 と例外まで一致することを確認した（角度2の ImageJ 18プローブは全て実物と一致、新規ゼロ）。

### 観察（欠陥に数えない）

- R の波括弧なし1行形式 `if (cond) 文 else 文`（10試行）は「未対応：else」で停止する。実 R は受理する形式だが、アプリは構文（else を含む1行形式）を挙げた未対応宣言として停止しており、値の捏造・虚偽原因はないため観察に留める。
- CloudFormation の `Ref` は、モデルに定義済みのパラメータ（`Stage`）への参照でも解決されず、断片がそのまま返る。参照解決自体がこの種類の対象外という設計であり、未定義の `Condition` 名／`Ref` も同じ素通りになる（未定義だけが特別に化けるのではない）ため、角度1では欠陥に数えない。

## 角度3：短絡評価と評価順序（32プローブ → 新規ゼロ）

全角度で実物と一致した。

- JavaScript／Python／R／AutoHotkey／C#：`&&`／`||`（R は `&&`／`||`、C# は `&&`／`||`）が正しく短絡し、回避された右辺の未定義名・0除算はエラーにならない。決定側では右辺が評価され、正直なエラーになる。Python の `or`／`and` の値意味論（`0 or "x"` → `"x"`、`5 and 7` → `7`）も正しい。
- 非短絡の対照も正しい：VBA の `And`／`Or` は実物どおり短絡せず、右辺の 0除算がエラー11相当（「0 で除算しました」）になる。R の `&`、C# の `&`（bool）も両辺評価され、右辺のエラーが表面化する。
- C／C++：`(x != 0) && (10 / x > 1)`（x=0）が短絡でエラーにならず 0 を返す。
- ImageJ：`0 && zzz`、`1 || zzz` とも右辺が評価されてエラーになるが、これは実物の仕様どおり。公式ソース `ij/macro/Interpreter.java` の `getLogicalExpression2()` は左辺の値によらず右辺を常に評価してからビット演算で結合しており、短絡しないことが一次情報で確認できた。
- 既知との重なり（数えない）：JavaScript の代入式の被演算子位置 `(x = 1) + (x = 2)` の「) が必要です」は RG-06（R11-N11）の既知表面。C／C++ の前置 `++i` を式に埋め込む形の解析失敗は RG-06（R12-N11）の既知表面。
- Power Apps は角度3の対象外とした（0除算がエラー値でなく Infinity 化する RG-02 の既知欠陥のため、短絡の有無を観測できない）。

## 角度4：スコープとシャドーイング（38プローブ → 新規1件）

正しかった表面（抜粋）：

- Python（6件）：if ブロック内の代入が外で見える、ループ変数が最終値で残る、関数ローカルが漏れない、関数内の代入が大域を変えない、関数内の同名読みは大域を参照する、`UnboundLocalError`（関数内で代入する名前の代入前読み）まで実物どおり。
- JavaScript（6件）：`let` のシャドーイング、ブロック外からの `let`／for-`let` 参照の ReferenceError、`var` のブロック漏れ・for-`var` の残留まで全て実物どおり。
- C／C++：シャドーイング（内側 2・外側 1）、ブロック内宣言・for 変数の外側参照は名前を挙げたエラー、for 初期化子でのシャドーイング（合法）も正しい。
- C#：ブロック内宣言・for 変数の外側参照はエラー、兄弟ブロック同士の同名宣言（合法）は正しく受理される（下記 N8 の禁止は入れ子関係に限られる）。
- ブロックスコープを持たない種類（VBA の手続きスコープ＝If 内 `Dim` が外で見える・ループ変数が 4 で残る、R、ImageJ、AutoHotkey、Power Fx の `Set`／`UpdateContext`、Power Automate、UI.Vision）は全て実物どおりフラットに振る舞う。

### R20-N8（P3・新規／新規群 RG-77相当）C# の入れ子宣言スペースでの同名シャドーイングを無言で受理する

- 一次情報：Microsoft Learn「Compiler Error CS0136」および C# 言語仕様 — 「ローカル変数宣言スペースと入れ子の宣言スペースが同じ名前の要素を含むことはエラー。どちらか一方が他方を含む関係にない宣言スペース同士なら同名でもよい」（順序には依存しない）。
- 再現（3表面、同根）：(a) 入れ子ブロックでの同名宣言が 2／1 とシャドーイング動作する、(b) for 初期化子での同名宣言が受理され外側の 9 が残る、(c) 内側ブロックが先・外側の宣言が後でも受理される。実 C# では3つ全て CS0136 コンパイルエラー。
- 対照：兄弟ブロック同士の同名宣言は実 C# でも合法で、アプリも正しく受理する（アプリが一律に同名を禁止しているわけではなく、C-family 共通の「シャドーイング可」モデルを C# にも適用していることが切り分けられた）。C／C++ ではシャドーイング自体が合法で、アプリの同形コードも正しい。
- 受け入れ条件の目安：C# で入れ子関係にある同名宣言が CS0136 相当の名前を挙げたエラーになり、兄弟ブロックの同名と C／C++ のシャドーイングには回帰がないこと。
