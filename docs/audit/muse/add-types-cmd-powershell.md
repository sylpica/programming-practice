## 0. 前提と全体ルール

- 対象：新規に2種類を追加する。**コマンドプロンプト（cmd）** と **PowerShell**。種類の id は既存の命名規則に合わせて `cmd`／`powershell` とし、表示名は「コマンドプロンプト」「PowerShell」とする。
- 2種類とも、既存13種類と **完全に同じ利用体験** を提供すること（詳細は §2）。種類セレクタで切り替えられ、種類ごとに下書き・状態が保持されること。
- 進行順序：ローカルで2種類の実装と再検証を終える → 節目の1回で配信する。配信ルールの詳細は §7 に従うこと。
- `PROGRESS.md` は節目コミットの中に同梱して更新すること（単独 push 禁止）。対象を「全15種類」に更新し、2種類の状態行を追加すること。監査対応レポートは `docs/audit/CODEX-R6.md` に新規作成し、種類ごとの実装範囲（対応した／正直な未対応とした構文・コマンドの一覧）と検証結果を具体的な数値で示すこと。ユーザーが自分で検証する必要のない形で報告すること。
- 対応・未対応の宣言は `docs/DEVELOPMENT.md` に2種類分を追加し、実装と一致させること。
- フロントエンドの実装に触れる場合は Modern Web Guidance（GoogleChrome 公式スキルパック）の導入を試み、関連ガイドを参照すること。導入の成否（環境制約で不可の場合を含む）を報告に含めること。ただしベンダー実施ベンチマーク由来のガイドであり、従来の監査基準・共通UIルール（スクロールを減らす／文字の切れを作らない／説明文は下の方へ）が優先する。

## 1. 実装の大原則

1. **既存の枠組みに乗せる。** 「定義データ＋種類ごとのモジュール」（`js/types/<id>/` ＋ `registry.js` への登録）で追加し、共通基盤（パス列挙・trace・最終状態・使用中チップ・ファイル取り込み・テンプレート／リファレンス／用語集の各画面）を再利用すること。共通基盤の拡張が必要な場合は、既存13種類の挙動を変えない形で行い、その旨を CODEX-R6.md に明記すること。
2. **誤った値の捏造と、虚偽の原因表示は不可。** 実装できない構文・コマンドは、構文名・コマンド名を挙げた「未対応」の正直な宣言で停止し、宣言（DEVELOPMENT.md の対応・未対応リスト）を実装と一致させること。正直な未対応化は劣化ではなく、受理可能な実装として扱う。
3. **仮想マシンは作らない。** シミュレーションは、変数・出力・仮想的な現在フォルダとファイル一覧の範囲で完結させる。実ファイル操作・実プロセス実行は行わない。実環境でしか決まらない値（実ファイルの内容、実コマンドの成否など）は捏造せず、入力モデル（実行時に決まる値）として扱うこと。
4. **表示は各シェルの正規表記に合わせる。** trace・出力・最終状態の3表面で矛盾させない。実在しない表示形式を作らない（例：PowerShell のオブジェクトはプロパティを持つ形で示し、内部表現の生JSONや `[object Object]` のような表示を出さない）。

## 2. 共通要件（既存13種類と同一の利用体験）

- **4画面**：コード練習／リファレンス／テンプレート集／用語集。リファレンスには §3 に挙げたコマンド／コマンドレットと構文要素を、既存種類と同程度の粒度で収録すること。用語集には2種類の基本用語（環境変数、終了コード、パイプライン、オブジェクト等）を追加すること。
- **テンプレート**：種類ごとに基礎〜応用まで学習に使えるテンプレートを複数用意し、種類ごとの偏りがないこと（既存種類と同程度の本数が目安。具体的な本数は CODEX-R6.md に種類別に明記）。テンプレート解説は実行シミュレーションの下に全展開表示とし、解説から用語・リファレンスへ飛べること。
- **コード説明／実行シミュレーション2モード**：実行ボタン式と、コード更新時に常時表示が追随する式の両方。エラーは行と原因を示すこと。説明文クリックで該当行へジャンプ＋自動スクロールすること。
- **分岐パスの全列挙とナビゲーション**：if／for 等の分岐から取りうるパスを全部表示し、左右切替・件数表示（n/N）・ソート・先頭／末尾ジャンプ・番号指定ジャンプを提供すること。**パスの上限は2,000件** とし、上限に達した場合はその旨を告知して打ち切る（無言で欠落させない）こと。条件ラベルは、学習者がコードと対応づけられる表記にすること。
- **使用中チップ**：コードで使用しているコマンド／コマンドレット・組み込み要素を、使用中パネルにパス連動で表示し、押すとリファレンスの説明が開くこと（既存種類の「使用中の関数」チップと同じ仕組みに、コマンド／コマンドレットを載せる）。
- **終わったときの状態**：変数は右パネルに出さず、下部の「終わったときの状態」に表示すること。cmd は環境変数の一覧と ERRORLEVEL、現在フォルダを、PowerShell は変数とパイプライン最終値、現在フォルダを、それぞれ含めること。
- **入力モデル**：実行時に決まる値（ユーザー入力、実環境依存の結果）は値を捏造せず「実行時に決まる」ものとして扱い、入力候補の列挙・組み合わせの剪定は既存種類の入力モデルと同じ規則で行うこと。
- **ファイル取り込み**：ドラッグ＆ドロップでコードに反映できること。拡張子は cmd が `.bat`／`.cmd`、PowerShell が `.ps1`。
- **共通UIルール**：スクロールはなるべく減らし主要コンテンツと操作を一画面に収めること、文字の切れ・はみ出し・実質縦書き崩れを作らないこと（375px 幅を含む）、免責・説明のような恒常文は画面の下の方に置くこと。

## 3. シミュレーション範囲の目安

範囲の正本は一次情報とする。cmd は Microsoft Learn の Windows コマンドリファレンス、PowerShell は Microsoft Learn の PowerShell ドキュメント。ここに挙げた範囲を超える実装をしてよいが、挙げた範囲は原則として対応し、それ以外は §1-2 の正直な未対応とすること。対応範囲の最終的な線引きは CODEX-R6.md と DEVELOPMENT.md に明記すること。
