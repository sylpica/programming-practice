## 保留と未確定（理由）

1. **RG-12（Power Fx の暗黙変換）**：Microsoft Learn の演算子／データ型ページは型付きリテラル間の暗黙変換を定義せず、変換は Value() 等の関数として提示され、coerce は Dynamic／型なし値についてのみ文書化されている。二次資料は `=` の大小区別で矛盾する。推測で実装せず現行の型厳密な挙動を維持。確定には実ランタイム（Power Apps Studio／pac power-fx REPL）での確認が必要。
2. **Power Fx の `Blank() = 0`／`Blank() = ""`（198件に不算入の未確定候補）**：Learn「Understand errors in Power Fx」は算術演算での blank の 0 への強制のみを述べ、等値比較は未定義。IsBlank の解説は `Value = Blank()` が空文字列と区別されることは支持するが、0 については確定できない。DAX の規則（`BLANK() = 0` が真）は厳密比較 `==` を持つ別言語のもので転用しない。現行挙動（両方とも偽、`Blank() = Blank()` は真）は Learn が支持する表面と矛盾しないため変更せず、留保として記録する。
3. **RG-04（R の表示2点）**：空ベクトルの `numeric(0)` 等の表記には要素型を持つ空ベクトルが必要だが値モデルに無く、既存テストも `c()` を固定している。長さ1の表記ゆれ（リテラルと計算結果）も既存テストが両側を固定。いずれも3表面内では相互に矛盾しない。
4. **RG-37／RG-57 の実ブラウザ確認**：意味構造の是正と下書きロジックは実装し、ロジックは単体テストで検証済み。実ブラウザでのフォーカス順・スクリーンリーダ実測と下書きのフロー確認は、配信前の親工程で実施する項目として残す。
5. **C系の `(long long)` キャスト**：既存テストが名指し停止を要求するため現状維持（名指し未対応として停止する）。
6. **AHK の RG-55 残余表面**：コアが生成する trace 注記の一部（`not` 演算子経由）で生の boolean 表示が残る。値と分岐は正しく、表示注記のみの残余として記録する。
7. **Python の範囲外観察**：異なる NaN オブジェクトを含むリストの順序比較と、NaN キーの辞書同一性は今回の findings の対象外であり、観察として記録するに留める。
8. **VBA Replace の空検索文字列＋start**：Microsoft 文書の文言から実装したが逐語検証は未実施。再監査の対象としてフラグを残す。
