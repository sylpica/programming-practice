## 2. CMD-34（cmd /c 入れ子引用符）の回帰確認

前回ラウンドで Microsoft Learn の cmd /c 引用符規則により裁定・閉鎖した件の回帰確認。

- 単純形 `cmd /c "echo hello"` → 出力 "hello"。
- 入れ子形 `cmd /c "echo "a b""` → 出力 `"a b"`（引用符つき）。
- 判定: 両形とも前回ツリーと出力が完全一致。Learn の規則（引用符保持の条件を満たさない場合は先頭の引用符と閉じの引用符を落として残りを実行する）とも整合する。**閉鎖を維持する。**

## 6. ゲート結果

- **UTC 全スイート: 7,512件中 7,509 合格／3 失敗。** 失敗は全てパス上限のタイミング系で、いずれもテスト自身の壁時計予算（10秒）を使い切った形:
  - `cmd path cap is explicit and never exceeds the common 2000 paths`（10,009ms）
  - `default maximum is exactly 2000 paths`（10,219ms）
  - `powershell path explosion emits a notice at the shared 2000 path cap`（10,111ms）
  対照裁定: tests/cmd.test.js 単独 **41/41 合格**（path cap 含む）、tests/engine.test.js 単独 **43/43 合格**。powershell の1件は単独実行でも他班スイートとの競合下では失敗したが、診断スクリプトで同一処理を測ると **壁時計 10,218ms に対し CPU 時間 1,145ms** であり、エンジン自身の壁時計予算が VM の CPU 競合（共有1.5 CPU に他班のスイートが並行）で消費された環境要因であることを実測で確認した。コードの回帰ではない。なお親の独立検証では同一コミット 4771801 で UTC／JST とも 7,512 件全通過が確認済みである。
- **JST 全スイート: 7,512件中 7,509 合格／3 失敗。** 失敗は UTC と同一の3件（cmd path cap 10,003ms／default maximum 10,220ms／powershell path explosion 10,084ms）で、全て壁時計予算の使い切り。JST 側の対照でも、cmd 版の同一処理を診断すると **壁時計 10,026ms に対し CPU 時間 626ms**（探索は1パスで時間上限により停止）であり、競合による CPU 飢餓が失敗機構であることを直接実測した。エンジン版・powershell 版も同一の共有パス上限機構・同一の失敗形であり、UTC 側の単独対照合格（41/41・43/43）と親の独立検証（両 TZ 全通過）と合わせて、3件ともタイミング系の環境要因と裁定する。A1 の担当表面に起因する失敗は JST でもゼロ。
- A1 関連4ファイルは JST でも 148/148 全通過（タイムゾーン依存の失敗は A1 の範囲にない）。
- precache: 本ラウンドは出荷ファイルを変更していないため再生成は不要。`node scripts/precache.mjs --check` は現行ツリーで合格（docs/audit は precache 対象外）。

## 7. 観察事項（新規欠陥ではないもの）

- UV-32 の表示小瑕疵（停止文面で変数名が途切れる）は前回残存のまま同一形で残存。新規ではない。
