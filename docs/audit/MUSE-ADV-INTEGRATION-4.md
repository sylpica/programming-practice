  A8 の cpp 事前検査ブロックが同一挿入点に重なった。両者は独立した検査

  `__ncls` 名指し停止を直列に保持した。

  （simple／A4）、impl-advanced-math.js は自動マージで合成した。
- scan／カタログ配線の統一：実効カタログ `__catalogReference` の設定は
  `js/app.js`（2箇所）と `js/worker.js`（1箇所）のみが行い、cmd／csharp／
  imagej／javascript／powershell／python の各 scan は基礎カタログへの

  「実効カタログで照合する」原則は単一であり、二重配線・片肺が残って
  いないことを統合ツリーで確認した。

## 3. 横断 §5 の再測結果

実測プローブは監査作業領域の `work/int4-probes/`（b7-sweep＝層化365件、
reach＝到達性291件）に保存した。

- §5-1（KD-1／KD-2）：簡易ラインが是正し解消（RG-637）。
- §5-2（RG-634）：簡易ラインが表示層で是正し解消（RG-638）。
- §5-3（層化365件の scan／trace 到達）：統合実測は **scan 264/365・
  trace 197/365** で、A7 ライン単独実績（244／168）を下回らなかった。
  残りの未達はクラス／属性形と未検証項目であり、A7 の静的限界の裁定
  どおりとする（RG-662）。
- §5-4（std:: 修飾名の scan 挙動）：統合後も不変であることを実測で
  確定した（`std::cout` は基礎の cout へ解決、`std::sort(...)` は
  未解決）。A8 の cpp 事前検査は実行側の是正であり、scan 側は残存と
  して確定する（RG-662）。
- §5-5（complex.conjugate の到達）：統合直後の再測で後退が残っていた
  （222/291、conjugate 未達）。原因は、候補が complex.conjugate と
  numbers.Complex.conjugate の2件に増えたことと、exprHint に二項／
  単項の型推論がなく `(3+4j)` の受け手の型が定まらず一意性フォール
  バックが働かなかったことである。数値の型昇格に基づく型推論を
  `js/types/python/index.js` の exprHint に追加して是正し、**scan
  225/291**（conjugate／complex.real／complex.imag を回復、統合第1弾
  時点の 223 を上回る）となった（RG-661）。
- §5-6（高度モードでの基礎 scan の喪失）：math.sqrt／numpy.array は
  A7 の是正で回復していたが、list.copy／set.copy 経由では list.append／
  set.add が落ちていた。メソッド呼び出し結果の型が伝播していなかった
  ためであり、項目の returns 接頭辞から既知の型名に限って型を伝播
  させるよう exprHint を是正した。横断班の4例全てで高度 scan が簡易
  モードと一致した（RG-661）。
- 統合側の是正2件の回帰テストは `tests/muse-adv-integration4.test.js`
  （7件）。是正後の安定性は b7-sweep 264/197・reach 225/291 の再測で
  確認した。
