## 5. 新規実質欠陥 2件（修正済み）

### CONV-A6-01：基礎 str.format 項目の文面が実挙動と矛盾

`js/types/python/index.js` は基礎項目 8件（open、str.format、random、json、os、
datetime、numpy.array、pandas.DataFrame）に supported=false を設定し、注意書きへ
「このアプリのシミュレーションでは未対応として停止する。」を追記する。しかし
str.format はブロックB6で単一エンジンに実装され、簡易モードでも実行できる
（例は「2 + 3 = 5」を出力。キーワード引数・書式指定も動作し、引数不足は項目
自身の pitfalls どおり IndexError）。修正バッチ8の裁定（参照専用分類は簡易
モード表示用に残す。`tests/muse-fix-batch8-ui.test.js` の R29-N4 テストが
str.format を停止検証から除外している）に従い、**分類は残したまま追記だけを
差し替え**た：「str.format 自体は本アプリでも実行できる（この項目は未対応
分類の参照専用として残している）。」（Python の caution 文体＝常体に合わせた）。R29-N4 の在庫不変条件（参照専用項目の
caution は「未対応」を含み「未確認」を含まない）にも適合する形にしてある。

### CONV-A6-02：基礎 with 項目の文面がプロトコル実装前のまま

基礎項目 with（`js/types/python/reference.js`）の summary／pitfalls が
「__enter__／__exit__ は再現されず、as 変数には未確定値が入る」という部分
モデルの文面のままだった。実測（簡易モード、実 CPython と全点一致）：
W1 __enter__ が 42 を返すと as 変数は 42、W2 本文の例外で __exit__ が呼ばれ
False なら伝播、W3 __exit__ が True を返すと例外は抑制、F5 __enter__ のみの
クラスでは本文実行後に __exit__ 欠落の AttributeError。プロトコルを持たない
対象（`with 5`）だけが従来の部分モデル（未確定値・停止なし）に落ちる。
RA-20 の時点で with は supported=true とされ、開示は項目文面が担う設計だった
ため、**文面のみを実挙動へ修正**した（summary と pitfalls を差し替え）。
新 pitfalls は RA-20 テストと Y-5 文体規則（Python の caution は常体が多数派）
の制約を満たす形にした：プロトコル定義オブジェクトでは __enter__／__exit__
まで再現すること、非プロトコル対象では「部分対応である：本文は実行されるが、
as 変数には未確定値が入り、後始末は再現されない」ことを明記する（「部分対応」
の出現は1回のみで、対象を非プロトコル対象に限定した）。

付随する同期：照合台帳 `docs/audit/reference-r2.json` の with／str.format 行
（python／cloudformation の計4行）の fields と sha256 を現行定義から再計算
して更新し、`tests/muse-fix-batch2-fc-python.test.js` の固定 sha も追随させた
（sha の正規方式＝fields の sort_keys・ensure_ascii=False の JSON の sha256 で、
旧行4件の再計算が保存値と一致することから方式を検証した上で更新）。

回帰テスト：`tests/muse-lane-a6-conv.test.js`（新規2件）で両欠陥の文面と
実挙動（str.format の実行・IndexError、with の W1〜W4）を固定した。
