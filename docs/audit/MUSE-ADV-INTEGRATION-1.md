## 2. 解消した継ぎ目

共有ファイル（app.js／worker.js／registry／precache.mjs／sw.js／c-family.js）の
編集は統合役が一元的に担った。

1. **エンジン拡張フックの接続（RG-596）**：機構の applyCatalog は高度データの
   読み込みだけで、契約のフック `applyAdvancedEngine` を呼んでいなかった。
   app.js の applyCatalog（合成成功時のみ。フック例外時は読み込み失敗と同じ扱いで
   基礎カタログへ倒す）と、実行用 Worker の双方へ接続した。Worker は実行ごとに
   再生成されメインスレッドの有効化を引き継がないため、実行メッセージの
   advanced フラグで同じ手順（loadAdvanced→mergeCatalog→フック）を再現する。
2. **有効カタログの差し込み（RG-596）**：種類側の scan／名前解決が有効カタログを
   参照できるよう `definition.__catalogReference` を app.js／worker.js に新設した。
   未設定の環境（ブロック単体テスト等）では各種類の従来動作になる。
3. **有効化は一方向（RG-597）**：各ブロックの有効化に解除手段は無く、モードを
   簡易へ戻しても解除しない。モードが切り替えるのはカタログ・表示・名前解決の
   範囲であり、実行結果はモードで分岐しない（契約の原則どおり）。
4. **WDL のレジストリ設計（RG-598）**：powerautomatecloud は `definitions`
   （16種）へ入れず `advancedOnlyDefinitions` として分離した。基礎カタログの
   件数表明・ピンは簡易モードの種別集合に対するものであり、混入させると基礎側の
   全件数が壊れるため。getDefinition は両集合から引き、検証も両集合に適用する。
   表示は高度モードのみで、簡易へ戻る際は下書きを退避して基礎種別へ落とす。
5. **Power Automate デスクトップ種別の名称（RG-599）**：改名しない（U-47 の実質は
   既存種別の無変更）。クラウド側は「Power Automate（クラウド）」で区別する。
6. **CFN 注記（notes）の描画（RG-600）**：index.html に `#resultNotes` を新設し、
   simulate 結果と scan 結果の注記を高度モードでのみ描画する。
7. **検索述語の拡張（RG-601）**：renderRefs／fullRefs の述語を共通ヘルパー
   `refSearchText` へ一本化し、項目の `inventoryNames` と `scan` を索引に含めた
   （B5 §3 の機構側要件）。束ね項目へ統合された棚卸し名から自項目へ到達できる。
8. **B1 差異 D-1／D-2／D-3 の解消（RG-602／603／604）**：D-1（静的合成）は実害なし
   としてブロック設計を残置し、機構側の正をフックとした。D-2（precache 収載）は
   機構契約の除外を正として B1 のピンテストを契約側へ追従させた。D-3（scan 静的
   解決）は有効カタログ連動の絞り込みを実装した。
9. **precache（RG-595）**：機構側の除外パターン（ファイル名 advanced-manifest.js／
   advanced-engine.js／「-advanced」を含む .js）を正本として再生成し `--check`
   合格。高度データファイルの混入ゼロを機械確認した。なお新種別
   powerautomatecloud の本体ファイルは通常種別と同じく precache 対象であり、
   表示可否はレジストリとモードで制御する（データ差分ではないため）。
10. **c-family.js の競合解消**：B6（C ライブラリ）と B8（C++ エンジン）が同じ
    アンカーへ挿入した競合は両方を保持して解消した。B5 との3領域の競合は言語別に
    切り分け（C ライブラリの戻り型→C# の呼び出し戻り型、C++ メンバー型→C# の
    メンバー型スーパーセット、C ライブラリ呼び出し→C# の高度呼び出し）の順で
    両立させた。
11. **C の表明文と malloc 実装の緊張（RG-611）**：semantics の support 文を実態へ
    是正した（高度モードの C のモデル対応を開示、C++ の new／delete は高度でも
    未対応と明記。C++ の new が未対応で停止することは実走で確認）。

## 3. B6 申し送り A-X(d) の是正（RG-605）

- 第1段：名前解決を有効カタログへ配管。レシーバ型ヒント（bytes／bytearray／
  frozenset／memoryview）の追加、属性は束ね項目より個別項目を優先、組み込み
  呼び出し・演算子からの object.__*__ 暗黙解決。
- 第2段（独立再実測の指摘を受けて）：数値ヒントの int／float／complex 細分化
  （float.real 等の誤リンク4件を解消）、型名レシーバ、属性の汎用解決、暗黙解決の
  追加（累積代入・添字・for・with・クラス生成・format）、トレース経路の短名突合せ。
- 第3段：代入・削除文脈で __getitem__ が付く誤リンク M1 を、対象文脈で
  __setitem__／__delitem__ へ出し分けて是正。frozendict のヒントも追加。
