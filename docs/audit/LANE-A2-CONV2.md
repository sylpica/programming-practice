- **JST 失敗の裁定（全て環境要因・欠陥ではない）**: 2回目の失敗3件は (1) `audit nested macro cross product reports the 2000 path cap`（探索上限の早期発動で停止）、(2) `cmd path cap is explicit and never exceeds the common 2000 paths`（10,084ms、「1 !== 2000」）、(3) `powershell path explosion emits a notice at the shared 2000 path cap`（10,010ms、同形）。いずれも「2000パス上限」を実時間予算（10秒）で検証するテストで、本ラウンド中は他班のスイート実行が並行し VM（共有1.5 CPU）が強く競合していた（全量所要時間が UTC 225秒 → JST 571〜672秒に伸長）。
- **対照実験**: (a) 該当3ファイルを個別実行すると audit.test.js は 1,541／1,541 全通過。(b) **無変更の正本 repo-reffix（同一コミット 4f41e11、清浄ツリー）でも cmd の同テストが同一形（10,081ms）で失敗**し、powershell はタイミングにより正本で 104／104 通過した。(c) 親が静穏条件で実施した同一コミットの独立実測は UTC・JST とも 7,535／7,535 全通過であり、自ツリーは正本とバイト同一（本班はコード変更を行っていない）。(d) 第1回報告書 §5 でも同一署名の失敗が正本対照つきで環境フレークと裁定されている。以上により、JST の失敗は全てタイミング系フレークと裁定し、欠陥として数えない。期待値の変更は行っていない。
