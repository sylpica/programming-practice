## 3. 新規欠陥と修正（重要度別）

### P2

**P2-1. UI.Vision: 条件位置のエラーで !statusOK が true のまま残る**
if／while の条件式の失敗はコマンドディスパッチャを経由しないため、ディスパッチャ側の !statusOK 書記を迂回し、エラーで終わったパスでも !statusOK=true と表示された。項目自身の説明と公式仕様（"Once an error happens !statusOK is set to FALSE"）に矛盾。
修正: `js/types/uivision/index.js` の simulate 後処理で、エラーを持つパスは !statusOK を false に是正し、最終状態グループを再生成する。

**P2-2. cmd: 展開修飾（部分文字列・置換）が宣言に反して停止し、遅延形は黙って空に化けた**
`%S:~0,3%` 等は「未対応」で停止（項目「変数展開」は対応宣言・除外の開示なし）。さらに遅延形 `!S:~0,3!` は名前全体を変数名として引いて黙って空文字になっていた（%形より悪い無言の化け）。
修正: `js/types/cmd/engine.js` に修飾子解釈（`applyExpansionModifier`）を新設し %形・!形の双方で実装。意味論は SET ヘルプ文／SS64: 部分文字列（負数は末尾から）、置換は大小区別なし全件置換、`*検索=置換` は「先頭から最初の一致まで」全体を1つの一致として置換文字列に置き換え（一致なしなら不変）。未確定値の修飾結果は捏造せず未確定のまま保持、未定義変数は R26-N23 どおりリテラル保持、解釈不能な修飾子は従来の名指し停止。あわせて `js/types/cmd/index.js` の項目「変数展開」と semantics.support の宣言を実装に一致させた。
注記: 実装途中で `*` 形の意味論を SET ヘルプ文で再確認し、「削除して残りを置換」から「範囲全体を置換文字列に置換」へ是正した（一次情報の文面が決め手）。

**P2-3. cmd: expose の停止理由が偽の原因（DiskPart と誤記）**
項目は DiskShadow／VSS（caution 明記）なのに停止理由は「DiskPartの内部コマンドで…」と別仕組みを主張。
修正: 停止理由を DiskShadow／VSS の文面へ（`js/types/cmd/advanced-engine.js`）。

**P2-4. cmd: set shadow copy が自項目の名指し停止に届かない**
基礎 set の接頭辞検索エラーが先に発火し、項目名を挙げない誤帰属の停止になっていた。
修正: `js/types/cmd/engine.js` の dispatch で、基礎コマンド名で始まる複合名停止（現行は set shadow copy／set environmental variables の2件のみであることを全数列挙で確認）を基礎処理より先に照合する。どちらの形も基礎 set では正常実行にならないため正規呼び出しを奪わない。

**P2-5. cmd: 実コマンド名の表記ゆれが理由なしの未知コマンド扱いに落ちる**
`manage-bde -status`、`powershell_ise`、`rundll32 printui.dll,PrintUIEntry` が「未対応のcmdコマンド」という理由のない停止になっていた。
修正: 停止照合に正規化語列（ハイフン／アンダースコア分割＋語尾の `.`／`,` 以降を切断）を追加。停止文はカタログ名（manage bde／powershell ise／rundll32 printui）で出る。停止表への追加はしていない。

### P3

**P3-1. UI.Vision: storeEval 等の文入力が被演算子を原因として名指す**
`storeEval` に `throw 1` を渡すと「この構文は説明に対応していません：1」と文ではなく被演算子を原因化していた。
