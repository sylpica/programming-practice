## 3. B4 の処置

### 3.1 差異(a) 静的合成（RG-615）

B4 は VBA インタプリタが共有 `js/engine.js` 内にある制約から、フック方式でなく engine.js／`js/types/r/index.js` のフックブロックによる静的合成を採っていた。第1弾の B1 差異 D-1 処置（RG-602）と RG-597 の原則（単一エンジン。モードはカタログ・表示・名前解決の範囲だけを切り替える）に照らし、この形を正として確定した。純粋なテーブルモジュールは B4 側で分離済みであり、無理な移設はしない。帰結として簡易モードでも B4 実装分の関数はエンジンとして実行可能であり、簡易モードの表面（掲載範囲・状態・件数）は基礎カタログのままであることを突合せと実ブラウザで確認した。

### 3.2 差異(b) precache

B4 ツリー同梱の再生成版（高度ファイルを含む）は採用せず、機構の除外パターンで統合ツリー側で再生成した（§6）。

### 3.3 §5 テスト期待値8件の裁定（RG-616）

B4 取り込み直後の全スイートは 5,557件中10件失敗で、内訳は §5 の裁定対象8件＋棚卸しパス2件だった。プローブで実挙動を確認したうえで、次のとおり裁定した（いずれも一次情報に反していた期待値の訂正であり、弱体化ではない）。

1. R `sqrt(readline())`（batch13-r）：エラー停止の期待を、未知伝播（「（実行時に決まる値）」を印字）の期待へ是正。同テスト内の as.numeric と同じ扱いが実 R の意味論に合う。
2. VBA CCur／CSng／CBool（batch10-vba）：停止の期待を実行値の固定へ是正（CCur(True)="-1"、CSng(True)="-1"、CBool(True)="True"、CBool(0)="False"、CCur(1.5)="1.5"。実 VBA と一致）。
3. StrConv／Shell／CallByName（batch8-cfnvba）：StrConv は実装済みのため実行（"ABC"）を固定。Shell／CallByName は名指し停止のまま。
4. FormatDateTime／VarType／Weekday（batch8-vbasweep・2テスト）：「参照専用例が停止する」期待を「エラーなく実行できる」へ是正。VarType(42)=5 はエンジンの統一数値モデル（数値リテラルは Double＝vbDouble）による規約として根拠を明記した。GetAttr／Dir は名指し停止のまま。
5. 棚卸しパス（adv-b4-r-data1・2テスト）：ツリー相対位置の差異のため両対応にした（照合内容は不変）。

是正後は関係ファイル14本・264件が全件合格した。

### 4.2 差異(b) フック位置づけ（RG-623）

Python の高度マニフェストは engineFile に B7 の `advanced-engine.js` を採り、その `applyAdvancedEngine` が標準ライブラリ登録の唯一の入口である。engine.js 内の汎用ディスパッチはレジストリの有無でガードされ、未有効化時の基礎挙動に影響しない。

### 4.3 Python エンジンの三方向マージ（RG-624）

`js/types/python/engine.js` は B6 統合済み版（6,577行）と B7 版（4,706行）が基礎（4,295行）から独立に伸びていたため三方向マージを行い、競合14塊を合成した（結果 6,988行）。両者の拡張は値の族が互いに素（B6：ユーザーインスタンス／bytes／complex／memoryview、B7：ネイティブ値／ネイティブクラス／モジュール）なため原則併置としたが、属性アクセスの `__class` ディスパッチだけは両者が同じ基礎行を別実装で置き換えており、併置により B7 側の単純な classLookup 行が B6 の getAttrClass（classmethod 束縛・super・MRO・dunder 属性）を横取りする実回帰が出た（B6P3 の6テスト失敗で検出）。基礎行の正統な後継は getAttrClass であるため、B7 側の行は置かず、B7 の例外属性・ネイティブ属性の行だけを前に併置して是正した。是正後は関係テスト全件合格。

同根の期待値是正として、G5 の matmul（RG-626）：B6 の特殊メソッド機構により `operator.matmul(V(), V())` は `__matmul__` が発火して 42 を返す（CPython の意味論どおり）ため、B7 単体時点の前提に基づく停止期待を是正した。

### 4.4 差異(c) precache と棚卸しパス

precache は B7 側未実施が正であり、統合側で機構の除外により再生成した（B7 の全ファイル名が除外パターンに一致することは B7 側で検証済み）。B7 の g5／u テストが参照する棚卸しファイル（`adv-b7-tools/`）はツリー相対位置の差異のため両対応にした（RG-625。照合内容は不変）。
