## 4. 裁定 C1〜C11 と根拠

- **C1 ÷ の意味**：記述形式に商か実数除算かの区別なし。試験では整数の文脈で商として使われるのが常態で、実数を含む場合は実数除算が要る。よって**値駆動**とした：両辺が整数（整数リテラル・整数型由来）なら商（0方向への切捨て）、実数（小数点リテラル・実数型宣言由来）を含むなら実数除算。mod は `a - trunc(a/b)*b`（被除数符号）で ÷ と整合させた。`の商` の句は常に trunc。
- **C2 文字列の +**：記述形式に連結演算子は無いが、問題文で定義される演算として + の連結が使われる前提で、文字列・文字との + を連結として採用した。借用である旨を項目（+）の caution と semantics に明示した。
- **C3 添字の始点**：別紙2に明文はないが、全問題の注記で1始まりが常態化している（具体例は別紙1にも明示）。問題ごとの注記差を再現する機構は持たず、**1始まりに固定**し、その旨を配列型の項目に明記した。
- **C4 二次元の2表記**：別紙2は `a[行, 列]`、R6問3 は `edgeList[i][1]`（配列の配列）。両形式をサポートし、値の形（対象が二次元配列か配列の配列か）で解釈する。
- **C5 表記揺れの正規化**：`X型配列の配列`＝`X型の配列の配列`、`X型配列`＝`X型の配列`（R6問2 の表記揺れが根拠）。全角／半角の glyph（＋－＝＜＞：，（）［］｛｝・全角英数字）は同一視する。for 制御記述の空白揺れ（`1から始めて` 等）も吸収する。
- **C6 未定義**：別紙2「値が格納されていない状態を未定義といい、`未定義の値` を代入すると未定義になる」。値として実装し、代入・初期化・配列要素・比較（＝／≠／が未定義である）を可能にした。未定義のまま演算すると名指しエラー。宣言のみで未代入の変数も未定義状態。
- **C7 for 制御記述**：記述形式は文法を定義していない。実例で確認した3形式（基本形・R7問1 の変形・R6問5 の for-each）だけを受理し、それ以外は対応形式を案内して名指し停止する。
- **C8 日本語条件句**：実例で確認した8形（と等しい／でない／以上／以下／より大きい／より小さい／未定義である／未定義でない）だけを受理する閉じた集合とした。
- **C9 宣言なし代入**：R6問3 に宣言なし変数への代入の実例があるため許す（試験互換）。未宣言変数の**読み取り**は名指しエラーとした（実例は代入のみ）。
- **C10 配列の可変長**：末尾追加で伸びる（リスト問題の前提）。範囲外の添字の読み書きは名指しエラー（黙って伸ばさない・黙って未定義を返さない）。
- **C11 リテラル**：文字列・文字は二重引用符のみ（実例は全て二重引用符。一重引用符は別紙3＝表計算の表記で混同禁止）。文字／文字列の区別は宣言型の文脈で表示し、内部表現は文字列で統一した。

その他の裁定：and／or は短絡評価（記述形式に評価順の規定なし。未確定の左辺で決着する場合は右辺を評価しない）。引数はスカラー値渡し・配列／オブジェクト参照渡し（サンプル問2 の逆順が呼び出し側に反映する前提）。再帰は共通 LIMITS.depth で制限。0除算は名指しエラー。

## 5. 未定義関数・メソッド・コンストラクタの扱い（正直な開示）

擬似言語は「プログラム中で定義されていない関数は問題文で定義されている」前提の言語である。エラーにすると試験問題のコードが軒並み実行できなくなるため、次で統一した：

- 未定義の関数呼出し：戻り値を**未確定値（実行時に決まる）**とし、トレースに「プログラム中で定義されていないため、戻り値は実行時に決まるとして扱います」と注記する。エラーにはしない。
- メソッド呼出し：同じく戻り値は未確定値とし、その旨をトレースに注記する。
- コンストラクタ呼出し：インスタンスは生成するが、メンバの初期化は問題文の定義を再現できないため、メンバは未定義として扱う。この旨をトレース・semantics・クラス型／メンバアクセスの項目 caution で開示する（U-45 の「未対応・未検証を判別できる形で明示」に相当）。
