## 3. 新規実質欠陥 1件（修正済み）：CONV2-A6-01 ヌルポインタと整数 0 の等価比較

### 観察と一次確認（gcc 13.3.0 実走）

A8班の観察「C モードで `printf("%d", NULL == 0)` が `0` を出力する（実 C は `1`）」を
gcc で一次確認した：`NULL == 0` → 1、`NULL != 0` → 0、`p == 0`（p は NULL）→ 1、
`0 == NULL` → 1、関数戻り値のヌルポインタ `== 0` → 1、`NULL == NULL` → 1、
`!NULL` → 1、条件位置の NULL → 偽、の全形が定義どおりの値になる。

### アプリ側の実測（修正前）

値モデル：ヌルポインタは JS の `null` で表され（NULL リテラル・ポインタ変数・
関数戻り値のいずれも同じ表現）、実ポインタは `{kind:"pointer", object, offset}`。
修正前の等価比較の実測：

| 形 | 実 C | アプリ（修正前） | 判定 |
|---|---|---|---|
| `NULL == 0` | 1 | **0** | 誤値 |
| `NULL != 0` | 0 | **1** | 誤値 |
| `int *p = NULL; p == 0` | 1 | **0** | 誤値 |
| `0 == NULL` | 1 | **0** | 誤値 |
| `strchr("abc",'x') == 0` | 1 | **0** | 誤値 |
| `int b = (NULL == 0);` | 1 | **0** | 誤値 |
| `NULL == NULL`／`p == NULL` | 1 | 1 | 一致 |
| 実ポインタ `== 0`／`!= 0` | 0／1 | 0／1 | 一致（CF-02 経路） |
| `NULL < 1`／`NULL <= 0`（関係演算） | 1 | 1 | 一致 |
| `!NULL`／条件位置 | 1／偽 | 1／偽 | 一致 |

### 真因

`js/core/c-family.js` の `binary()` は、ポインタ実体同士・実ポインタ対 null／0 の
比較を CF-02 ブロックで正しく処理するが、**ヌルポインタ値（JS null）と数値の比較**は
末尾の `baseBinary` 委譲に落ち、JS の緩い等価（`null == 0` は false）で評価されて
いた。関係演算は JS 側でも null が 0 に読み替えられるため一致しており、等価比較
だけが実 C と逆になっていた。NULL 項目の文面（returns：「void* へのポインタ、
または整数の 0」、caution：「ポインタへの代入と比較に使えます」）はこの相違を
開示しておらず、むしろ 0 との等価を含意するため、開示済みモデル差には当たらない。

### 裁定と修正

(a) 実質欠陥として共有核で根本修正した（`js/core/c-family.js`、+19行）：
unmanaged（C／C++）の等価比較（==／!=）で、一方がヌルポインタ値（null）で
他方が数値（または null）の場合、null を 0 として比較する（C11 6.3.2.3／6.5.9 の
ヌルポインタ定数の変換規則）。ゲート条件により、C#（managed）の null 比較、
実ポインタとの比較（CF-02 ブロック）、関係演算・真理値の経路は一切変えていない。

### 修正後の検証（同根の波及点検を含む）

- 上表の誤値6形は全て実 C と一致する値に是正（変数代入形・連鎖形 `(NULL == 0) == 1`
  を含む）。従来一致していた表面（NULL 同士、実ポインタ対 0、関係演算、真理値、
  条件分岐の慣用形）は全て不変。
- 境界形：`NULL == '\0'` → 1、`NULL == 0.0` → 1（gcc の警告つき数値比較と一致）、
  `NULL == 1` → 0／`NULL != 1` → 1、確保失敗の NULL（calloc 上限超過）`== 0` → 1、
  整数変数 `z = 0` との比較 → 1（gcc の警告つき比較と一致）。
- **C++ への波及（是正方向）**：nullptr も同じ JS null 表現のため、C++ の
  `nullptr == 0` → 1、`nullptr != 0` → 0、`int *p = nullptr; p == 0` → 1 と実 C++ に
  一致するようになった（修正前は C と同じ誤値）。A8班の std::NULL 名指し停止
  （事前検査層）は本修正の対象外で不変。A8班へは共有核側で是正済みの旨を引き継ぐ。
- 残る停止（いずれも修正前後で不変、誤値ではない）：`NULL + 0` は型不一致の
  CompileError で停止（ヌルポインタへのポインタ演算は C11 でも未定義動作であり
  停止自体は正直。理由文が汎用文言である点は観察として記録）、`printf("%d", NULL)`
  は書式不一致の未定義動作停止、`(long)NULL` は名指し未対応停止。
